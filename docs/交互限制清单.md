# 交互限制清单 —— 哪些"拦住用户"是必要的，哪些是多余的

> 起因（用户 2026-10-13）：
> 「这个限制我之前就觉得用起来不爽，在别的地方也改掉，会有什么影响吗？」

这份文档回答两件事：**① 到底有哪些地方会拦你；② 每一处该不该改。**

---

## 一、先说结论

我把页面里所有"视频开着就如何如何"的判断都过了一遍。
用 `clip`（当前的播放上下文）当守卫的地方一共 5 处，**只有 1 处是多余的**，
而你说"用起来不爽"的那个，**其实不是那句提示，是地图的自动跟随**。

| 位置 | 拦的是什么 | 判定 | 处理 |
|---|---|---|---|
| 地图点击 | 视频开着时不换选点 | **多余**（限制） | **已删掉** |
| 地图自动跟随 | 视频一开就替你动视野 | **过度主动** | **已改**（见第三节） |
| `exportClip` | 没播放就不给导出 | 必要 | 保留 |
| 右键画面打点 | 没播放就没有"当前帧" | 必要 | 保留 |
| 空格键暂停 | 没开视频就不接管空格 | 必要 | 保留 |

**其他操作一个都没被视频挡** —— `Find flights`、覆盖面板、图墙、标记点、
检测生成、报告，全都能在视频开着时用。这点是查过的，不是感觉。

---

## 二、那条多余的：视频开着不能换选点

原来是这么写的：

```js
map.on('click', e => {
  if (clip) { show(mapNotice, 'While the video is open, clicking the map does not change the selection...'); return; }
  ...
});
```

**"怕把正在对照的检索结果打乱"** 这个理由是站不住的 ——
用户点地图就是他明确想换个位置看。而且真要保护，正确的做法是
**让播放内容不动**（已经这样了），而不是干脆不让他选。

现在改成（用户 2026-10-13 定的规则）：

> 无论视频是否在播放，点击之后就是新的点，然后就可以按新位置去搜索；
> 但直到点开对应帧的照片画面，才会更换右侧播放的视频内容。

配套：换选点会**清掉旧图墙**（不然新坐标配旧图，点进去跳到别处 —— 这是个真隐患）。

## 三、真正"不爽"的那个：地图自动跟随

### 原来的行为

```
L1609 / L2383   followViewport()          ← startClip 一进去就调；之后每帧遥测也调
FOLLOW_MIN_INTERVAL = 1500 ms            ← 每 1.5 秒可以自动动一次
FOLLOW_USER_GRACE   = 5000 ms            ← 你拖动地图后只"让位" 5 秒
```

而且 **"Follow · Fit" 是 HTML 里写死的默认值，没有记忆**：

```html
<option value="fit">Follow · Fit</option>   <!-- 默认就是它 -->
```

`initFollowMode()` 当初只认 URL 参数 `?follow=off`，不读任何存储。

于是实际体验是：

> 每开一个视频，地图就自动跟着飞机跑；你拖开看一眼，**5 秒后又被收回去**；
> 改成 `No follow`，**下次开视频又变回跟随**。

那个下拉框还藏在**视频面板标题栏、紧挨着关闭按钮**的位置，不显眼。

**这和第二节那个限制是同一类毛病：默认替用户做了主，还不记住他的选择。**

### 改法（用户选的「A + 半 B」）

**A. 记住选择**

```js
const FOLLOW_MODE_KEY='droneMap.followMode';
function readSavedFollowMode(){ try{ ... }catch(e){ return null } }   // 隐私模式不崩
function saveFollowMode(v){ try{ ... }catch(e){} }
```

- 启动时：**URL 参数优先**（`?follow=off` 便于分享固定视角），没有才用记忆
- 改下拉框时：立刻写下来

**半 B. 点选点时当次不跟随**

```js
let followSuppressedByProbe = false;
```

- 地图点击设 `true` —— 他正在看**这个位置**，别把视野收回飞机上
- `followViewport()` 一进来就检查它；命中就返回，并给一句说明：
  `Map follow is paused for this selection — pick a follow mode (or drag the map) to resume.`
  （避免他以为跟随坏了）
- **跟随模式本身不变** —— 这不是"关掉跟随"，只是不跟他这一下抢
- 解除的两个时机：**改跟随模式**（明确表态）、**拖动地图**（他已在主动掌控）

### 为什么不做完整的 B

完整 B 是"用户拖过地图就永久不再自动跟随"。代价是**要拆掉
`followRestorePending` 那套「5 秒后收回来」**，而有人就是靠它
"我随便看看，它自己回到飞机上"。**这是个真实取舍，不该我替他决定**，
所以先做半 B —— 让位只发生在"他明确表示在看别处（点选点做检索）"时。

## 四、保留的三处，为什么必要

**`exportClip`（导出 ±5 秒片段）**

```js
if(!clip){ videoStatus.textContent='No video is playing. Open one and then export.'; return; }
```

它导出的是"以**当前位置**为中心的前 5 秒 + 后 5 秒"。没有播放就没有"当前位置"。
这是**方向依赖**（先有 A 才能做 B），不是限制。硬要改只能编一个位置出来，那才是错的。

**右键画面打点**

打点要用**当前帧**的画面反算地面落点 —— 需要 `clip` 里的遥测和播放位置。
同理，方向依赖。

**空格键**

```js
if(!clip) return false;   // 没打开视频时不接管，让空格照常作用于页面按钮
```

这是**不抢页面按钮的键**。没视频时空格该照常滚动/点按钮。

## 五、测试

新增 `test_follow_mode.js`（21 套测试之一），钉住三件事：

```
页面脚本不抛异常 /
跟随模式会记住（off / center / 没存过用默认 fit）/
改下拉会写进 localStorage /
localStorage 被拒时不崩（源码级确认异常被吞掉）/
点选点 -> 置位抑制，但模式不变、也不偷偷写偏好 /
抑制检查排在「按模式分支」之前 / 抑制时给出说明 /
改跟随模式 = 抑制解除 + 记住新选择 /
用户拖地图 = 抑制解除 /
URL 参数优先于记忆
                                        全部通过
```

> 写这个测试时踩了一个**自己的坑**：我原本想"把 sandbox.localStorage 换成一个会抛的对象"
> 来验隐私模式，结果发现页面里的 `readSavedFollowMode` 是从沙箱**解构**出来的，
> 闭包已经绑到原来那个对象上，**换属性对它无效** —— 等于验了个假。
> 改成正常路径 + 直接读源码确认异常被吞掉。

## 六、给你的自检清单

以后遇到"某功能好像被什么挡住了"，按这个顺序查：

1. `grep 'if(clip)'` —— 是不是"视频开着"在拦
2. `grep 'if(!clip)'` —— 分清**拦截**和**方向依赖**（后者是合理的）
3. `grep 'localStorage'` —— 是不是某个选择**没被记住**，每次都要重设
4. 看**默认值** —— HTML 里的 `selected`、JS 里的初始赋值，最容易被当成"固定行为"

第 3、4 条是这次真正的收获：**"用起来不爽"往往不是被拦住，
而是系统每次都替你把旋钮拧回默认值。**
