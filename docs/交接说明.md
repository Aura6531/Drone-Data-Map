## 一、这是什么

把 DJI 无人机的飞行遥测与视频对齐的**本地工具**：点地图上任意位置，
就能跳到那一刻、那个位置拍的画面。核心卖点是**地图 ↔ 视频同步**。

- 前端：`Code/project_geojson_preview.html`（单文件，界面与逻辑都在这）
- 后端：`Code/project_manager.py`（HTTP 服务 + SRT 解析 + ffmpeg 调用）
- 测试：仓库根目录 `test_*.js` / `check_page.js` / `check_py.py` / `test_geocode.py`
- 数据：`Data/`（不进仓库）；项目定义：`Project/`（本地状态，不进仓库）

## 二、跑起来

```bash
cd Code
python -B project_manager.py        # 固定绑定 127.0.0.1:8000
# 浏览器打开 http://127.0.0.1:8000/project_geojson_preview.html
```

**依赖**：Python 3.10+（必需）、FFmpeg（抽字幕流/转码才需要）、天地图 key
（`Code/tianditu_key.txt`，**不进仓库**，缺失时底图可切 OpenStreetMap）。

**Windows 沙箱注意**：如果后端写入 `Code/`、`Project/`、`Data/` 时报
`PermissionError [WinError 5]`，说明启动它的进程没有这几个目录的写权限 ——
需要以完全权限启动（这些目录缺少沙箱的继承授权 ACE）。
仓库里带了一个诊断技能：`diagnose-windows-sandbox-acl`。

## 三、必须先知道的约定（违反就会出问题）

1. **只处理 DJI 标准命名**：`DJI_YYYYMMDDHHMMSS_NNNN_X`（`_V`/`_S` 可见光、`_T` 热成像）。
2. **GeoJSON 的要素级 `properties` 必须含 `point_times`** —— 地图检索、视频跳转、
   飞机箭头同步全部依赖它。缺了就"点得到、跳不准"。
3. **`generate_geojson_for_video` 读的是同名 `.srt` 文件**，不依赖 MP4 里是否还有字幕流。
   所以剪辑过的素材只要把同名 `.srt` 放回去，就仍能生成轨迹。
4. **高度是相对起飞点**；相机视场框与「画面取点」都基于**平地假设** ——
   俯角大（近处）准，接近平视会明显偏（实测 1° 俯仰误差 ≈ 112 m）。
5. **删除项目 ≠ 删除数据**：只移除 `Project/<名字>/`，`Data/` 一律不动。
   文件列表里的「删除」只删该视频对应的 GeoJSON（含 3D 版）与 SRT，**绝不碰 MP4**。
6. **SRT 遥测字段**（`/api/project/telemetry` 提供，按视频）：`times/alt/yaw/pitch/focal/dzoom`。

## 四、检索「A+B」是怎么工作的（最近一次主要改动）

用户点地图某点后，不再只找"无人机离它最近"，而是：

```
B（筛）把目标点反投影回图像 → (xImg,yImg) ∈ [-1,1] 即"这一帧看得见"
A（排）在看得见的帧里，按"该帧画面中心点到目标的地面距离"取最近
回退   pitch>=0 打不到地面 → 不参与判定
       focal 缺失 → 用广角基准 BASE_FOCAL=24mm
       全部不可见 → 退回"无人机位置最近"，并在结果里标 inFrame=false
```

- 数学：`frameCenterLatLng()`（正投影，复用 `groundPointForImage`）
  与 `imagePointOfGround()`（反投影）**严格互逆** —— 由 `test_ab.js` 保证
  （往返误差 ~1e-12）。改这两处务必先跑它。
- 遥测来源：检索要跨所有已加载航迹，所以按视频预取并缓存
  （`telemetryByPath` + 挂在航迹对象上的 `t.telemetry`，供同步读取）。
- 预取未完成时会先给回退结果，**300ms 后自动重搜一次**（`scheduleResearchAfterPrefetch`）。

## 五、全屏

**只有一条路**：`<video>` 自带控件里那个全屏按钮 —— 浏览器把 video 单独全屏，
外面的浮层由 `fullscreenchange` 给对话框加 `native-fs` 类隐藏
（标题栏/小地图/红外/信息行）。真铺满、零黑边。

曾经的「对话框铺满（theater）」那套（含自制全屏按钮）**已整体删除**，
不要再加回来 —— 它在全屏下始终有黑边，且容易和原生全屏打架。

页面里仍留着两处 theater 残迹：空的 `syncFullscreenBtn()`（给旧调用点留的壳）和
关窗时的 `classList.remove('theater')`（清历史类名）。它们是**故意保留**的兼容壳，
`check_page.js` 专门断言这两处存在 —— 想彻底清干净得连断言一起改，别只删代码。

测试路径一律按**脚本所在目录**推导（`__dirname` / `__file__`），换机器、换盘符都不用改；
node 套件可用 `node test_ab.js <html路径> <数据目录>` 覆盖，python 套件用 `PYTHON=…` 指定解释器。
环境：Node 18+ / Python 3.10+（node 不一定在 PATH 里，用完整路径调用即可）。
`test_boot.js` 会把页面顶层脚本放进 DOM/Leaflet 桩里真跑一遍 —— 语法错误、

## 九、标记点功能

在视频画面上右键取点 → 命名 → 地图上落一个橙点；这些点全部**随项目保存**
（`Project/<项目名>/project.json` 的 `markers`，字段 `id / name / lat / lng / video / time / created`），
重开页面、切换项目都会自动读回。右栏下半就是它们的列表。

- **列表**（`renderMarkerList`）：按 `created` 升序（列表 / 导出 / 报告同一个顺序）；
  每行 `[✓] 名称 纬度 经度 [×]`；表头「全选」带**半选态**（`markerSelectAll.indeterminate`）；
  标题旁计数写成「已选 n / 共 m」。
- **四个动作**都只作用于**勾选的点**；一个都没勾就点 → 直接页面 alert 提示
  （按钮**不**因为没勾而禁用，这是要求）：
  - 删除：单个 × 与批量删除**都要二次确认**（`deleteMarkers(ids,true)`）。
    只改项目里的 markers，**不动视频和数据文件**。
  - 导出 KML：前端拼 XML + Blob 下载，文件名 `标记点_<项目名>_<日期>.kml`。
    坐标是 `经度,纬度,0`（KML 的顺序，写反了会飞到南极），名称做了 XML 转义。
  - 复制经纬度：`名称\t纬度\t经度` 制表符表格进剪贴板（优先 `navigator.clipboard`，
    失败退回 textarea + `execCommand`），可直接粘进 Excel。
  - 生成 Word 报告：先弹窗选截图尺寸，再逐个点跑 逆地理编码 → 抽帧 → 地图截图，最后拼 docx
    （见本节末尾）。
- **点一行 = 跳转**（`jumpToMarker`）：地图 `setView(..., TRACK_FOCUS_ZOOM=16)`；
  视频按标记点里存的 `video` 反查 `geoFiles` 得到 `folder_index`，再用
  `openVideoFromPopup(..., false)` 定位到 `time` 那一帧 —— **只定位、不自动播放**
  （`clip.autoPlay=false`，`startClip` 加载完元数据后停在那一帧等用户点播放；
  轨迹气泡的「从点击位置播放」等入口不传这个参数，仍然自动播）。
- **测试**：`test_markers.js` 把上面这些函数从页面里抽出来、配最小 DOM 桩真跑
  —— 排序 / 半选态 / 行结构 / 单个与批量删除 / KML 坐标与转义 / TSV / 跳转载荷
  / 未勾选提示 / 报告按钮的依赖停用，都断言到了。`test_report.py` 覆盖报告后端
  （逆地理编码拼装与缓存 / 底图跟随 / 瓦片上限 / 抽帧两档 / docx 书签与超链接目录）。
  改这一块务必先跑它们。

**批次②（Word 报告，已完成）**：只含勾选的点，一个都没勾由前端提示。
报告 = 标题 + **可点击目录**（书签 + `w:hyperlink w:anchor`，**不是**要按 F9 刷新的域目录）
+ 汇总表（序号/名称/纬度/经度/所在位置/视频文件/视频时间）
+ 每点一节（字段表 + 图 1 视频截图 + 图 2 地图截图）。落 `report_cache/`，
文件名 `report_<时间戳>_<随机>.docx`，下载时用中文名 `标记点报告_<项目名>_<日期>.docx`。

服务端四条链路（都在 `Code/project_manager.py`）：

- `GET /api/reverse-geocode?lat=&lng=` → 天地图逆地理编码，拼 `省+市+区+镇+村`（字段去重；
  全空退回 `formatted_address`；取不到由前端写「未解析」，**绝不编造**），带内存缓存。
- `POST /api/snapshot` → `ffmpeg -ss <time> -i <原片> -frames:v 1`；`full` = 原始分辨率
  （4K 就是 3840×2160），`a4` = 缩到 2480px 宽（A4 正文宽 19.7cm @320ppi）。
- `POST /api/mapsnapshot` → 服务端 Pillow 拼瓦片（**复用 `tile_cache/`**，不重复下载），
  底图跟随前端传的 `basemap`：street = 矢量+注记 / satellite = 影像+注记 / osm = OSM，
  正中画红十字标出目标点。
- `POST /api/report/docx` → python-docx 生成；`GET /report/<名字>` 取回（只允许单层文件名）。

**两个必须记住的坑**：

1. **ffmpeg 直接写的 JPEG，python-docx 不认**。它写的是 `SOI + COM("Lavc…")`，
   而 docx 的图片嗅探只认 JFIF/Exif → `UnrecognizedImageError`，
   **而且这个异常的消息是空的**（接口只会返回 `{"error": ""}`，非常难查）。
   所以抽帧走「ffmpeg 出 PNG → Pillow 转 JPEG」；`test_report.py` 专门断言产出图带 `SOI+APP0`
   且 `docx.image.image.Image.from_file` 认它。
2. 报告依赖（python-docx / Pillow / ffmpeg）**延迟导入**：缺库时后端照常启动，
   `/api/config` 里如实报告 `report:{docx,pillow,ffmpeg}`，前端据此把「生成 Word 报告」
   按钮停用并在悬停里写明缺什么。
