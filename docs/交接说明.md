## 一、这是什么

把 DJI 无人机的飞行遥测与视频对齐的**本地工具**：点地图上任意位置，
就能跳到那一刻、那个位置拍的画面。核心卖点是**地图 ↔ 视频同步**。

- 前端：`Code/project_geojson_preview.html`（单文件，界面与逻辑都在这）
- 后端：`Code/project_manager.py`（HTTP 服务 + SRT 解析 + ffmpeg 调用）
- 测试：仓库根目录 `test_*.js` / `check_page.js` / `check_py.py` / `test_geocode.py`
- 数据：`Data/`（不进仓库）；项目定义：`Project/`（本地状态，不进仓库）

## 二、跑起来

```bash
cd Code
python -B project_manager.py        # 固定绑定 127.0.0.1:8000
# 浏览器打开 http://127.0.0.1:8000/project_geojson_preview.html
```

**重启服务**：仓库根目录有 `重启服务.bat`，**双击即可** —— 它先关掉占着端口的旧进程，
再以完全权限启动新的（等价于上面两条命令）。带一个参数可换端口：`重启服务.bat 8123`；
端口也能用环境变量给：`set UAV_MAP_PORT=8123` 再启动。
脚本内容**刻意写成纯 ASCII**（中文在 cmd 里会按当前代码页被当成命令执行，踩过）。

**依赖**：Python 3.10+（必需）、FFmpeg（抽字幕流/转码才需要）、天地图 key
（`Code/tianditu_key.txt`，**不进仓库**，缺失时底图可切 OpenStreetMap）。

**⚠ 改完后端（`project_manager.py`）必须重启服务才生效。**
页面 HTML 是**每次请求现读磁盘**的，而 Python 代码只在**进程启动时载入一次** ——
所以会出现最坑的一种情况：**界面是新的、接口却是旧的**（新接口一律 404，
前端报 `Unexpected token '<', "<!DOCTYPE "…` 或「服务端返回的不是数据，而是一个网页」）。
服务启动时会自己探一下 `127.0.0.1:8000`，如果有旧进程在应答就打一段提示（附 `netstat` / `taskkill` 命令）。

**Windows 沙箱注意**：如果后端写入 `Code/`、`Project/`、`Data/` 时报
`PermissionError [WinError 5]`，说明启动它的进程没有这几个目录的写权限 ——
需要以完全权限启动（这些目录缺少沙箱的继承授权 ACE）。
仓库里带了一个诊断技能：`diagnose-windows-sandbox-acl`。
另外：**以完全权限启动的进程，普通沙箱会话是杀不掉的**（`taskkill` 会 Access denied），
关服务得在同权限的终端里做。

## 三、必须先知道的约定（违反就会出问题）

1. **只处理 DJI 标准命名**：`DJI_YYYYMMDDHHMMSS_NNNN_X`（`_V`/`_S` 可见光、`_T` 热成像）。
2. **GeoJSON 的要素级 `properties` 必须含 `point_times`** —— 地图检索、视频跳转、
   飞机箭头同步全部依赖它。缺了就"点得到、跳不准"。
3. **`generate_geojson_for_video` 读的是同名 `.srt` 文件**，不依赖 MP4 里是否还有字幕流。
   所以剪辑过的素材只要把同名 `.srt` 放回去，就仍能生成轨迹。
4. **高度是相对起飞点**；相机视场框与「画面取点」都基于**平地假设** ——
   俯角大（近处）准，接近平视会明显偏（实测 1° 俯仰误差 ≈ 112 m）。
5. **删除项目 ≠ 删除数据**：只移除 `Project/<名字>/`，`Data/` 一律不动。
   文件列表里的「删除」只删该视频对应的 GeoJSON（含 3D 版）与 SRT，**绝不碰 MP4**。
6. **SRT 遥测字段**（`/api/project/telemetry` 提供，按视频）：`times/alt/yaw/pitch/focal/dzoom`。
7. **前端不要写 `scrollbar-width` / `scrollbar-color`**：Chrome 一看到这两个标准属性就改用
   「标准滚动条」并**忽略 `::-webkit-scrollbar` 系列规则** —— 去掉箭头按钮的样式会失效，
   于是列边缘又出现一条浅灰轨道 + 三角箭头（用户报的「模块边界上的浅灰直角」，实测顶部
   会多出一个三角形按钮）。标准属性只用 `@supports not selector(::-webkit-scrollbar)`
   包起来留给 Firefox，Chromium 走 webkit 规则。相关坑点记在 §十一。
8. **左列最后一张卡片要带 `card-fill`**：`.col-left` 是 flex 列，卡片不带 `flex:1` 时
   底边会比中/右列高出一截（文件少的时候尤其明显）。实测：加之前左列底边 910px、
   中/右列 983px；加之后三列都是 983px。

## 四、检索「A+B」是怎么工作的（最近一次主要改动）

用户点地图某点后，不再只找"无人机离它最近"，而是：

```
B（筛）把目标点反投影回图像 → (xImg,yImg) ∈ [-1,1] 即"这一帧看得见"
A（排）在看得见的帧里，按"该帧画面中心点到目标的地面距离"取最近
回退   pitch>=0 打不到地面 → 不参与判定
       focal 缺失 → 用广角基准 BASE_FOCAL=24mm
       全部不可见 → 退回"无人机位置最近"，并在结果里标 inFrame=false
```

- 数学：`frameCenterLatLng()`（正投影，复用 `groundPointForImage`）
  与 `imagePointOfGround()`（反投影）**严格互逆** —— 由 `test_ab.js` 保证
  （往返误差 ~1e-12）。改这两处务必先跑它。
- 遥测来源：检索要跨所有已加载航迹，所以按视频预取并缓存
  （`telemetryByPath` + 挂在航迹对象上的 `t.telemetry`，供同步读取）。
- 预取未完成时会先给回退结果，**300ms 后自动重搜一次**（`scheduleResearchAfterPrefetch`）。

## 十、地图上的注视指示线

从**飞机图标的机头**连到**准星**（相机中心在地面上的落点）的一条很浅很细的灰色虚线，
表示「飞机正在看向这边」。是别人提的建议，实现得不重：

- 样式：`LOOK_LINE_STYLE` —— `#9ca3af` / `weight:1` / `dashArray:'3,7'` / `interactive:false`
  （不接鼠标，免得挡住地图点击）
- 起点：`droneNoseLatLng()` 按**像素偏移**算 —— 图标 34px、锚点在中心，
  SVG 里机尖在 (20,3)，换算到图标上约 `DRONE_NOSE_PX=14`px；再沿 `droneBearing` 旋转
- 因为这个偏移是像素级的，**缩放后地面距离会变**，所以 `map.on('zoomend')` 时补算一次
  （视频在播时本来每帧都会重算）
- 生命周期：`syncCrosshair()` 里 `updateLookLine(drone,target)` 更新；
  `hideMapCrosshair()` 里 `hideLookLine()` 一起收掉 —— 关视频 / 关准星 / 清空地图都走它
- 测试：`test_sync.js` 验了四个航向（0/90/180/270）的机头方向与偏移量；
  `check_page.js` 钉住样式与调用点

## 九、标记点功能

在视频画面上右键取点 → 命名 → 地图上落一个橙点；这些点全部**随项目保存**
（`Project/<项目名>/project.json` 的 `markers`，字段 `id / name / lat / lng / video / time / created`），
重开页面、切换项目都会自动读回。右栏下半就是它们的列表。

- **列表**（`renderMarkerList`）：按 `created` 升序（列表 / 导出 / 报告同一个顺序）；
  每行 `[✓] 名称 纬度 经度 [×]`；表头「全选」带**半选态**（`markerSelectAll.indeterminate`）；
  标题旁计数写成「已选 n / 共 m」。
- **四个动作**都只作用于**勾选的点**；一个都没勾就点 → 直接页面 alert 提示
  （按钮**不**因为没勾而禁用，这是要求）：
  - 删除：单个 × 与批量删除**都要二次确认**（`deleteMarkers(ids,true)`）。
    只改项目里的 markers，**不动视频和数据文件**。
  - 导出 KML：前端拼 XML + Blob 下载，文件名 `标记点_<项目名>_<日期>.kml`。
    坐标是 `经度,纬度,0`（KML 的顺序，写反了会飞到南极），名称做了 XML 转义。
  - 复制经纬度：`名称\t纬度\t经度` 制表符表格进剪贴板（优先 `navigator.clipboard`，
    失败退回 textarea + `execCommand`），可直接粘进 Excel。
  - 生成 Word 报告：先弹窗选截图尺寸，再逐个点跑 逆地理编码 → 抽帧 → 地图截图，最后拼 docx
    （见本节末尾）。
- **名字查重**：右键取点时名字**不能跟已有的重复** —— `normalizeMarkerName` 去掉首尾空白、
  把内部连续空白压成一个、忽略大小写后比较；重名就**停在弹窗里提示、不入库**
  （`showVideoMarkError`，错误行 `#videoMarkError`）。默认名 `项目名-序号` 取最大序号 + 1，天然不重。
- **点一行 = 跳转**（`jumpToMarker`）：地图 `setView(..., TRACK_FOCUS_ZOOM=16)`；
  视频按标记点里存的 `video` 反查 `geoFiles` 得到 `folder_index`，再用
  `openVideoFromPopup(..., false)` 定位到 `time` 那一帧 —— **只定位、不自动播放**
  （`clip.autoPlay=false`，`startClip` 加载完元数据后停在那一帧等用户点播放；
  轨迹气泡的「从点击位置播放」等入口不传这个参数，仍然自动播）。
- **测试**：`test_markers.js` 把上面这些函数从页面里抽出来、配最小 DOM 桩真跑
  —— 排序 / 半选态 / 行结构 / 单个与批量删除 / KML 坐标与转义 / TSV / 跳转载荷
  / 未勾选提示 / 报告按钮的依赖停用，都断言到了。`test_report.py` 覆盖报告后端
  （逆地理编码拼装与缓存 / 底图跟随 / 瓦片上限 / 抽帧两档 / docx 书签与超链接目录）。
  改这一块务必先跑它们。

**批次②（Word 报告，已完成）**：只含勾选的点，一个都没勾由前端提示。
报告 = 标题 + **可点击目录**（书签 + `w:hyperlink w:anchor`，**不是**要按 F9 刷新的域目录）
+ 汇总表（序号/名称/纬度/经度/所在位置/视频文件/视频时间）
+ 每点一节（字段表 + 图 1 视频截图 + 图 2 地图截图），**节标题形如 `22. 东莞2-5`**
  —— 阿拉伯序号 + 英文句点 + 一个空格 + 点名；**不要用汉字数字**（原来写「二十二、」，
  用户要求改掉，`chinese_index()` 已删除）。落 `report_cache/`，
文件名 `report_<时间戳>_<随机>.docx`，下载时用中文名 `标记点报告_<项目名>_<日期>.docx`。

服务端四条链路（都在 `Code/project_manager.py`）：

- `GET /api/reverse-geocode?lat=&lng=` → 天地图逆地理编码，拼 `省+市+区+镇+村`（字段去重；
  全空退回 `formatted_address`；取不到由前端写「未解析」，**绝不编造**），带内存缓存。
- `POST /api/snapshot` → `ffmpeg -ss <time> -i <原片> -frames:v 1`；`full` = 原始分辨率
  （4K 就是 3840×2160），`a4` = 缩到 2480px 宽（A4 正文宽 19.7cm @320ppi）。
- `POST /api/mapsnapshot` → 服务端 Pillow 拼瓦片（**复用 `tile_cache/`**，不重复下载），
  底图跟随前端传的 `basemap`：street = 矢量+注记 / satellite = 影像+注记 / osm = OSM。
  **两套底图是分开的**：
  - **网页地图**默认街道图（`DEFAULT_BASEMAP='street'`，`<select id="baseMap">` 里街道项带
    `selected` —— `initBaseMap()` 读的就是 select 的值，两处必须一致）；
  - **报告地图**在「生成 Word 报告」确认弹窗里自己选（`<select id="reportBasemap">`），
    **默认卫星图**（`REPORT_DEFAULT_BASEMAP='satellite'`，选项里标「推荐」）——
    影像底图上红十字、飞机箭头和虚线都更好认。弹窗那句说明会实时显示当前选中的底图
    （`reportBasemapKind()` + change 监听）。
  - `runWordReport(list, mode, basemapKind)`：底图由调用方传入（弹窗选的那个），
    报告流程里**不再引用** `currentBaseMapKind` —— 改这块别又把两套底图搅在一起。
  没配天地图 key 时自动退回 OSM。
  截图 1600×640（2.5:1），报告里横向铺满、上下更扁。
  - **取景中心永远是目标点**（用户明确要求：目标最重要，飞机只是「知道在哪就行」）。
    `lat/lng` 就是标记点经纬度；`target_lat/target_lng` 仍然显式传一份 ——
    以后若再改取景方式，红十字的位置不会跟着跑偏。不给 `target_*` 时用取景中心。
  - **缩放默认 17 级**（18 级字更大，但视野太窄、周边参照物太少，反而不利于判断位置）。
    只有飞机快掉出画面时才降级：`reportMetersOffset()` 把飞机相对目标点的偏移拆成
    南北/东西分量，`reportMapZoomForOffset()` 从 17 往下逐级找（下限 10），
    直到两个方向都装得下（半幅 × `REPORT_MAP_MARGIN` 的余量）。
    17 级半幅 = ±352m（南北）× ±880m（东西）—— 飞机 100m 内、正东 300m 内都还是 17 级，
    正南 400m 才会降到 16 级。
  - **图注里的「缩放 N 级」用实际值**：`reportMapImageOf()` 返回 `{file, zoom}`，
    报告 payload 的 `zoom` 用它的值。**曾经这里写死 16**（`zoom:TRACK_FOCUS_ZOOM`），
    地图是 18 而图注写 16，对不上 —— 改这块记得别写死。
  - **飞机位置不依赖「航迹已加载」**：`reportTrackFor()` 先找 `loadedTracks`，没有就
    用现成的 `/api/project/geojson` 现取这条视频的 GeoJSON 并按路径缓存
    （以前只看 loadedTracks，页面刷新过 / 没点过「加载全部」就静默不画飞机 —— 踩过）。
  - 有飞机时后端画蓝色飞机箭头 + 「机头 → 目标点」的浅灰虚线，和地图页面上是同一种表达。
    **箭头形状照网页 SVG 的顶点比例**：机尖 (20,3)、翼尖 (34,34)/(6,34)、尾中缺口 (20,26)
    —— 相对 size 就是 `0.82 / 0.35`。曾经用 0.62/0.5，画出来比网页版窄一截（用户说「被压扁」），
    外接框比值 0.65 vs 网页版 0.90。
    **大小**：`DRONE_ARROW_SIZE = 24`（外接框约 39×44px，纸上约 2.9mm，和红十字半径 16 相当）。
    不能照网页的 34px 画 —— 报告图是 1600px 缩到 15.9cm（约 100px/cm），
    34px 的图标印出来只有 3.4mm、在 Word 里看约 9px，比网页版小得多。
    虚线起点 `DRONE_NOSE_PX` 要与 `DRONE_ARROW_SIZE` 一致（＝机头位置）；
    **前端网页上的 `DRONE_NOSE_PX=14` 是配 34px 图标的，不要跟着改**。
- `POST /api/report/docx` → python-docx 生成；`GET /report/<名字>` 取回（只允许单层文件名）。

**报告版面（实测定下来的数）**：一个点那一节要塞下「字段表 + 图 1 + 图 2 + 两行图注」，
必须都在同一页 A4 里。做法是**两张图都横向铺满正文宽**，只有太高的图才按高度上限回缩：

| | 高度上限 | 实际尺寸 |
|---|---|---|
| 图 1 视频截图（16:9） | `REPORT_VIDEO_IMAGE_MAX_HEIGHT_CM = 9.5` | 15.9 × 8.94cm（撞宽度上限，铺满） |
| 图 2 地图截图（2.5:1） | `REPORT_MAP_IMAGE_MAX_HEIGHT_CM = 6.6` | 15.9 × 6.36cm（铺满，上下更扁） |

`REPORT_IMAGE_MAX_WIDTH_CM = 15.9`，表格也是 **15.9cm**（用户在 Word 里量到两者都是
**6.26 英寸**，验证了这一点）—— 两者必须同宽，而且：

- **单元格边距必须显式写 0**（`set_docx_table_width` 里写 `w:tblCellMar` 上下左右全 0）。
  **这是「表格边框与插图对齐」的关键，也是反直觉的一条**：Word 定位表格是按
  **单元格里文字的起始位置**算的，不是按边框。所以 `tblInd = 0` 时文字落在正文左边距上，
  边框却被推到边距**左边一个「左单元格边距」**的距离 —— Word 默认左右 0.08 英寸
  （≈2.03mm），用户量到的「表格边框比照片多出约 2mm」正是这个数（他把它改成 0 后
  几乎严格对齐）。写 0 之后：文字起点 = 表格边框 = 左对齐插图的左边缘，同一个位置；
  而且 Word 与 LibreOffice 对 `tblInd` 的解释不同也不会跑偏。
- **插图段落左对齐**（`WD_ALIGN_PARAGRAPH.LEFT`，不是居中）。居中的话 15.9 会在 16.0 的正文区里
  两边各让 0.5mm，左边缘就跟表格差开。
- **表格缩进写 0**（`w:tblInd = 0`）：不给表格样式/阅读器留默认负缩进的余地。
- **列宽要同时写进「表格网格」和单元格**（`table.columns[i].width` + `cell.width`）。
  只写单元格的话 `gridCol` 还是 python-docx 建表时的默认等分（8.0+8.0=16.0cm），
  不同阅读器取哪个值不一致。
- **`tblPr` 子元素顺序要合 schema**：`tblW → tblInd → tblLayout → tblCellMar → tblLook`
  （`tblInd` 曾经被 append 到末尾、排在 `tblLook` 后面，虽然 Word 能忍，但按规范是错的）。
- `test_report.py` 有断言钉住这些：三张表宽度一致且 = 插图宽 = 15.9、单元格边距四项全 0、
  `tblInd = 0`、`tblPr` 子元素顺序。

热成像 5:4 那种方图铺满会有 12.7cm 高，会按高度上限回缩到约 11.9cm 宽（靠段落左对齐保持整齐）。

一节预算 ≈ 标题 1.0 + 字段表 3.7 + 照片 9.0 + 图注 0.7 + 地图 6.4 + 图注 0.7 ≈ 22cm，
A4 正文高 24.7cm，留约 2.7cm 余量。
**图与图注都居中**（`add_report_picture` / `add_report_caption`），图与图注用 `keep_with_next`
绑在一起，免得「图在页底、说明跑到下一页」。地图截图由前端按 **1600×640** 请求。
落盘的 JPEG 会写「诚实的 DPI」（像素宽 ÷ 目标显示宽），让按固有尺寸排的阅读器也算得对。

**别拿捆绑 LibreOffice 的整页光栅当尺寸依据**：实测它比实际页面对不上 —— 内容整体
放大约 10%、底部还会裁掉一截（`wp:extent` 和图片 DPI 它都不看）。判断分页看它报的
`pageCount`；Word 按 `wp:extent` 排，尺寸就是我们声明的那个。

**字体统一**（`set_report_font`）：中文走 `w:eastAsia = 微软雅黑`，西文与数字走
`w:ascii / w:hAnsi = Arial`。Normal / Title / Heading 1 / 目录里手写的超链接 run
都显式设定。

**真正的坑在这里**：样式里常带**主题字体引用** —— `w:asciiTheme="majorHAnsi"`、
`w:eastAsiaTheme="majorEastAsia"`，**它们的优先级高于 `w:ascii` / `w:eastAsia`**。
只写字体名不清主题引用的话，标题里的中文仍是主题的 **MS Gothic**、数字仍是主题的
**Calibri**（用户两次反馈「一个标题两种字体」就是这个）。所以 `set_report_font`
会把 `asciiTheme / hAnsiTheme / eastAsiaTheme / cstheme` 四个属性一并删掉。
（注意：捆绑 LibreOffice 渲染时 Arial/Calibri 都会被替换成度量兼容的克隆字体，
**光看渲染图分不出字体**，判断字体要看 docx 的 `styles.xml`。）

**表格内容**：统一「中部左对齐」—— 单元格 `w:vAlign=center` + 段落 `w:jc=left`
（`set_docx_cell` 与 `docx_point_field_table` 都设）。

**经纬度写法**（用户要求，方便复制粘贴）：数字**带正负号**，不带 N/S/E/W；
半球写在表头里 —— `纬度（°N）` / `经度（°E）`（汇总表列头与字段表左侧标签都是）。
所以 `format_latitude/longitude` 返回的就是 `f"{value:.6f}"`：
南纬/西经是负数。**用到南半球时**把这两个表头文字换成 `（°S）`/`（°W）` 即可
（都是常量/字面量，各一处）。
**用到国外时**：坐标本身、地图截图（Web 墨卡托，纬度已按 ±85.05 夹住）、
飞机与虚线都通用；**但「所在位置」走的是天地图逆地理编码，只覆盖中国** ——
国外点会显示「未解析」，真要支持得再加一个地理编码源（接口只认 `lat`/`lng`，
换源不用动前端）。

**两个必须记住的坑**：

1. **ffmpeg 直接写的 JPEG，python-docx 不认**。它写的是 `SOI + COM("Lavc…")`，
   而 docx 的图片嗅探只认 JFIF/Exif → `UnrecognizedImageError`，
   **而且这个异常的消息是空的**（接口只会返回 `{"error": ""}`，非常难查）。
   所以抽帧走「ffmpeg 出 PNG → Pillow 转 JPEG」；`test_report.py` 专门断言产出图带 `SOI+APP0`
   且 `docx.image.image.Image.from_file` 认它。
2. 报告依赖（python-docx / Pillow / ffmpeg）**延迟导入**：缺库时后端照常启动，
   `/api/config` 里如实报告 `report:{docx,pillow,ffmpeg}`，前端据此把「生成 Word 报告」
   按钮停用并在悬停里写明缺什么。
