# 逐点帧号（point_frames）：三路视频各自的精确帧号

> 用户 2026-10-15 的要求：「增加数据列嘛，对应：T 的帧数、V 的帧数、S 的帧数，
> 这样统一调用、查阅」

---

## 为什么不是"三列帧数"，而是"逐点帧号数组"

一次拍摄产出**三路视频**（同一架飞机、同一段航线、不同镜头）：

| 路 | 内容 | 分辨率 | 帧率 | 帧数 |
|---|---|---|---|---|
| `_V` | 可见光 4K | 3840×2160 | 29.78 | 36542 |
| `_S` | 同一视角 1080p | 1920×1080 | 29.75 | 36550 |
| `_T` | 热成像 | 1280×1024 | 30.00 | 36858 |

三路定位数据几乎相同（按时刻对齐只差 0~6 m），所以合并成**一份航迹**。
但**帧号各不相同、而且推不出来**：

- 三路帧率不同（29.75 / 29.78 / 30.00），跑 1228 秒累积出几百帧偏差
- 实测同一时刻 `T−V`：前 1/4 中位 **+50** → 后 1/4 中位 **+231**（漂移 181 帧）
- 三路各有丢帧（`FrameCnt` 不连续：V 49 处、S 10 处、T 11 处）

所以只存一个数字（"三列帧数"）不够 —— 跳到另两路会错约 5 秒。
改成**逐点存三路帧号数组**：

```json
"point_times": [0.0, 0.033, ...],
"point_frames": { "V": [0,1,2,...], "S": [0,1,2,...], "T": [0,1,3,...] }
```

---

## 前端怎么用（`framesOfHit`）

给定一条检索命中（含视频相对路径与时刻），算出**这一路自己的**精确帧号：

```js
framesOfHit(h) -> { stream, frame, seconds, all }   // 查不到返回 null
```

关键设计：

1. **哪一路**：命中的视频名后缀决定（`_V` / `_S` / `_T`）。
   合并航迹的文件名去掉了后缀，所以用航迹自己记的 `videos` / `video` 原名去对。
   **宁可漏（退化成老行为），也不能把别的架次的帧号拿来用。**
2. **哪一点**：按时刻找最近的采样下标（容差 `FRAME_MATCH_TOL`）。
3. **`seconds` 用合并航迹的 `times[i]`**，不是命中自带的时刻 ——
   这样"**显示的帧号**"和"**视频停下的帧**"必定是同一个采样点，
   不会出现"卡上写 18297、实际落到 18303"。
4. **`all`** 给出同一时刻三路各自的帧号 —— 这才是"三路差多少帧"的答案。

卡片上渲染成一行（`frameLineOf`）：

```
frame V 18297 · S 18282 · T 18433
```

顺序**固定 V/S/T**（不跟对象键顺序走），这样三张卡的这一行能竖着对齐比大小。

## 实测验证

### 真实数据（合并航迹 `DJI_20260924095258_0001.geojson`）

采样第 18271 点，`t=614.28 s`：

```
V: {"stream":"V","frame":18297,"seconds":614.28,"all":{"S":18282,"T":18433,"V":18297}}
S: {"stream":"S","frame":18282,"seconds":614.28,"all":{...同上...}}
T: {"stream":"T","frame":18433,"seconds":614.28,"all":{...同上...}}
frameLineOf -> "frame V 18297 · S 18282 · T 18433"
无帧号命中 -> framesOfHit 返回 null
```

**这组数字与我从 SRT 用 Python 独立算出的完全一致**（同一实测点
`t=614.280s  帧 {V:18297, S:18282, T:18433}`，三路差 151 帧 ≈ 画面差 5 秒）。
两条互不依赖的路径得出同一个答案 —— 这是可信度最高的一种验证。

### 测试（`test_frames_ui.js` 第 14 节，12 条断言）

```
[OK] V 路命中挂上 V 自己的帧号
[OK] T 路命中挂的是 T 自己的帧号（不是 V 的 18297）
[OK] 卡片上真的渲染出三路帧号（V/S/T 顺序固定）
[OK] T 路那张卡也列出同一时刻三路帧号 —— 用户一眼看出差多少帧
[OK] 对不上号的命中不会多出那一行（优雅退化）
[OK] 查不到帧号的命中身上没有帧号值
[OK] 跳播载荷里带着精确帧号（V 路）
[OK] 并标明是哪一路 —— 不会被拿去 seek 别的路
[OK] 定位到"帧号所在那一刻"（60.0，而不是命中自带的 59.9）
[OK] T 路跳转用的是 T 自己的帧号 18433
[OK] 没有帧号的命中，载荷里没有帧号
[OK] 没有帧号时定位时刻仍是 target_seconds（与改动前一致）
```

## 退化保证

**单路素材 / 老数据 / 360 全景**都没有 `point_frames`（360 是圆环几何，本来就没有
"帧号"这个概念）。此时：

- `framesOfHit` 返回 `null`
- `frameLineOf` 返回 `''`（整行不出现）
- 跳转用回 `target_seconds`，与这些改动之前**完全等价**

这条由上面那 3 条退化断言钉住。
