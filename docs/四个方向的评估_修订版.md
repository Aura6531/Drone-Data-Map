## 〇、这次修订的两句话

**1. 司空 2 的集成不再是「方向 3 里那个要赌一把的云方案」，它变成了四个方向共用的「数据来源」。**
连带地，两个大风险各降一级：**离线瓦片**有了官方答案、**元数据可得性**从"未知"变成"已验证"。

**2. 方向 3 的前提是"大疆面试通过 → 内部功能更新"，所以它衡量的不是"能不能做"，
而是"组织上谁来立项、有没有人已经在做"。** 技术可行性反而不再是它的瓶颈。

## 一、被验证 / 被推翻的假设

| # | 之前的判断 | 现在的事实 | 证据 |
|---|---|---|---|
| 1 | 「能不能拿到原始视频和 SRT 是关键，拿不到就只剩地图对齐」——**未知** | **拿到了，带字幕轨** | 实样 `DJI_20250704192536_0001_V.mp4`（从司空 2 媒体库下载，378.8 MB）：流为 `h264` + 2×`data` + **`mov_text`(3)** + `mjpeg`；抽 SRT 成功，345 KB / 5415 行 / 1083 定位点 / 361 个姿态采样点全部非空 |
| 2 | 转码是必然成本（本地素材是 HEVC，浏览器放不了） | **司空 2 的素材是 H.264，浏览器原生可播** | 该样本 `GET /api/project/video` 实测 `HTTP 206 / video/mp4 / Accept-Ranges: bytes`，不用走 ffmpeg 转码 |
| 3 | 方向 2「最大不确定性是离线瓦片」；没内网地图服务就得预下载 TB 级瓦片 | **司空 2 私有化官方就有离线地图服务**（卫星/栅格/路网 + 可视化部署 + 位置搜索），且私有化支持**自定义地图服务** | 官方发布记录标「仅国内」、底层百度（部署手册《百度离线地图服务》章）；部署手册另有 Custom Map Services 章 |
| 4 | 方向 1 和方向 4 是两件事，共用一个索引 | 更准的说法：**它俩是同一件事的两个出口** | 都在回答「我记得飞过哪，哪天来着」 |
| 5 | 司空 2 有「智能搜索」，可能和我们重了 | **不重**：它搜的是**文件名**，我们搜的是**位置** | 见第四节 |

### 关于第 3 条的展开（这是方向 2 掉下来的那块石头）

司空 2 私有化**官方提供离线地图增值服务**（发布记录原文）：

- 提供**卫星底图、栅格图、路网图**，支持**可视化部署**与**数据管理**
- **支持在私有化平台内做位置搜索**
- 但：**仅国内**，底层是**百度离线地图**（部署手册章节名就叫《百度离线地图服务》），且是**单独购买的增值模块**

同时，官方部署手册里有 **《自定义地图服务》/ Custom Map Services** 一章——说明**私有化司空 2 的瓦片源是可替换的**。

**对我们的含义**：

- 客户的司空 2 如果已经买了离线地图，**内网底图这件事客户那边已经花钱解决了**，我们只要对齐接口或直接用它的瓦片
- 我们的"可插拔瓦片源"因此**不只是技术整洁**，而是对齐了一个**被验证过能单独收费的模块**——而且我们能做得更宽（任意 WMTS + 免费）
- **海外项目它帮不上**（百度数据 + 仅国内），所以海外仍要我们自己配（Esri / Mapbox）
- 风险从「可能要预下载 TB 级瓦片」降为「加一层可插拔配置」——**方向 2 的最大技术不确定性基本消除**

## 二、修订后的四方向判断

### 方向 1：单机数据管理软件 —— ★★★★★（不变，但多了一个新场景）

原判断成立。新增的一点：**司空 2 的素材归档会持续增长**（你那个项目媒体已经 17.4 GB），
而**「从司空 2 落盘 → 本地对齐 → 检索 → 出报告」这条链今天已经被实样验证走通**
（建项目 → 挂目录 → 抽 SRT → 出 GeoJSON → 遥测 361 点）。

所以方向 1 多了一个**明确的输入口**：不只是"拖硬盘目录进来"，还包括"从司空 2 归档进来"。

### 方向 2：内网局域网平台 —— ★★☆☆☆ → **★★★☆☆**（升级，因为离线瓦片不再是未知数）

上升的理由只有一条，但很关键：**离线地图从"未知风险"变成了"两条已知路线"**。

剩下的硬活没变，仍然是**架构活**：
账号/权限、project.json → PostgreSQL、后台作业队列、对象存储/NAS、Docker 化、交付文档。

**结论仍然是：不要现在直接上**。但"并行去谈离线瓦片方案"这句可以改成
"**先问客户司空 2 有没有买离线地图**"——一句话就能定掉方案。

### 方向 3：完全上云 + 集成司空 2 —— **前提变了，性质也变了**

> **前提（用户 2026-10-12 补充）：方向 3 成立的条件是"接下的大疆面试通过，从而变成内部功能更新"。**
> 这一条把它从「对外产品」改成了「对内功能」，下面按这个前提重新判断。

**性质改变后，原来的商业风险整体消失：**

| 原风险 | 变成内部功能后 |
|---|---|
| 「给别人的平台做插件，命脉在对方手里」 | 不再适用——你就是对方 |
| 自建云：对象存储 / CDN / 认证 / 多用户 | **大部分不必建**：FH2 已有云存储（FlightHub Sync）、账号与权限、任务体系 |
| 视频流量成本（按量计费） | 由平台侧承担，不是我们算的账 |
| 云上底图 | 内部反而更容易（私有化有离线地图服务 / 自定义地图服务） |
| 「平台开放度未知」 | 变成内部接口对齐问题，不是外部审批问题 |

**所以方向 3 的正确形态是：不自建云，把现有工具做成 FH2 的一个功能。**
云、账号、存储、任务这些**不要再建一遍**；要做的只有"FH2 没有的那一段"——
**落地后的按位置检索 + 对齐取证 + 报告**（也就是方向 1 和方向 4 的出口）。

**但成功的关键因素换了一组，而且更不受我们控制：**

| 新的关键问题 | 说明 |
|---|---|
| **组织与归属** | 这个能力该落在哪个团队？（FlightHub 2 产品？行业应用？还是新方向）——不是我们能定的 |
| **是否已有人在管** | 内部可能已有"航后分析/数据检索"的规划或竞品方案，**这一点在外部完全查不到** |
| **优先级与档期** | 内部功能要排期，跟个人意愿无关 |
| **能不能进主流程** | 是"整合进 FH2 界面"还是"独立一个小工具"——前者门槛高得多 |

**结论修正：方向 3 的"技术可行性"从 ★★★☆☆ 升到 ★★★★☆（前提成立时），
但它的推进不该按"产品路线"来排，而该按"内部立项"来走——
先摸清归属团队、有没有重复建设、能不能进主流程。这三件事在拿到内部视角前无法判断。**

#### 面试场景的用法

如果方向 3 的目标是"面试通过后成为内部功能"，那**面试时最有价值的不是方案，是实证**：

1. **一个能跑的原型**（本项目现状）
2. **一个具体的缺口**：FH2 资源库只有"按文件名 + 创建时间"两个维度，
   而"我记得飞过哪、忘了哪天"这个真实场景没有入口 —— 这是**可复现的产品观察**，不是主观意见
3. **一条已经验证的技术路径**：FH2 下载素材带 `mov_text` 字幕轨 → 可本地对齐，
   **实测 1083 定位点 + 361 姿态采样点全非空** —— 这是"可以做"的硬证据，不是猜测

**这三样加起来，比"我想做一个平台"有说服力得多。**

#### 需要划清的一条线（务实提醒，不是法律意见）

本项目是**入职前、用自己的机器和素材**做的独立作品。入职后要注意：

- 面试时**主动说明**这是个人作品、以及它与 FH2 的关系 —— 说清楚比含糊更有利
- 入职后**新做的东西归公司**，这是常规；把"入职前的原型"和"入职后的功能"分开表述
- 素材来源与保密：面试演示用的素材（含今天这份司空 2 样本）**注意来源合规**

具体条款请以**你的劳动合同和公司知识产权政策**为准 —— 这一条我给不了判断。

### 方向 4：数据库 API 化 / AI 自然语言检索 —— ★★★★☆ → **★★★★☆**（证据链更硬了）

原来的"为什么现在的项目特别适合"三条仍然成立，现在再加两条：

1. **证据锚点已被实样验证**：视频有逐帧遥测（361 点姿态全非空）、照片有激光测距反解的坐标、
   **现在还能拿到司空 2 的变化检测结果**
2. **明确的市场缺口**：司空 2 的「智能搜索」是**按文件名**搜的
   （你截图里那排文件夹：`黄江停车场-FLY-TO-2025-09-14`、`牛山对比检测-3 2025-07-07`…），
   而那句真实需求「我记得飞过东莞东江边桥头镇，但忘记是哪天了」**在文件名里根本表达不出来**

**结论：方向 4 的判断不变，但它和方向 1 应该是同一个东西的两个出口。**

## 四、为什么「按位置找」是缺口（这条决定方向 4 的价值）

把三种"找"摆在一起看：

| 找法 | 司空 2 资源库 | 司空 2 智能搜索 | 我们 |
|---|---|---|---|
| 按文件夹翻 | ✅ 核心 | — | — |
| 按文件名搜 | ✅ | ✅ 核心 | — |
| **按位置找**（"东江边桥头镇那一块"） | ❌ | ❌ | ✅ **核心** |
| **按画面内容找**（"点这个位置，看那一刻的画面"） | ❌ | ❌ | ✅ |
| **按语义找**（"河道交汇口的数据情况"） | ❌ | ⚠ 仅文件名匹配 | ✅（方向 4） |

司空 2 的存储页只有"创建时间"一个排序维度。**"三个月前飞的，忘了哪天、忘了文件夹叫什么"**
这个场景，现在没有入口——**这就是方向 1 + 4 的全部意义**。

## 五、修订后的推进顺序

原顺序（索引 → AI 工具 → 按客户分支）**方向没错，但要改两点**：
把司空 2 归档提前到第 0 步一起做，以及先做一件更小的事来验证需求。

### 第 0 步（3–5 天）：**司空 2 归档导入**——先只做"落盘"这一段

理由：这是**唯一已经被实样验证的环节**，而且**不做接口也能先跑**。

- `project_import.html` 加数据源：**本地文件夹 / 司空 2**
- 司空 2 那一半先支持：**手动选一个本地目录当"司空 2 归档区"** → 扫 → 建项目 → 跑现成的 Build tracks
- 接口部分（列架次/取下载 URL）按 Apifox 字段写好、标 **未验证**，等私有化地址 + token 再接

**产出**：能从司空 2 的归档目录一键建出可检索的项目。**今天已经手工验证过整条链。**

### 第 1 步（2 周）：数据索引（SQLite + R-Tree）

和原评估一致，但**索引里要加两个字段**：`来源`（本地/司空2）和 `变化检测结果`（如果接）。

### 第 2 步（2 周）：把索引变成两个出口

- **人的出口**：一张总览地图（所有架次的覆盖范围）+ 按位置/时间筛
- **AI 的出口**：`find_flights(bbox, time)` / `search_track_points(bbox)` / `get_frames` / `get_map_image`
  → 先做**只读工具包 + OpenAPI 描述**（原评估的 A 形态）

**这两个出口共用后端，谁先做取决于你想先给谁看。**

### 第 3 步（按客户分支）

- 个人 → 方向 1 的界面继续做（去重、批量、统一地图）
- 政企 → 方向 2：**第一件事是问客户"司空 2 买没买离线地图"**，答案决定离线瓦片是接它的还是自建
- 海外 → **可插拔瓦片源 + Esri/Mapbox**（这条现在独立成了一小块，见下）

### 并行的一小块（1–2 天）：可插拔瓦片源

把 `tile_source_url()` 从"天地图特例 + osm"改成配置表。
**理由不再是"技术整洁"，而是**：对齐司空 2 的"自定义地图服务"能力 + 海外项目的前提 + 政企内网自建 WMTS。
**这是所有部署形态的公共前置**，而且改动面小。

## 六、现在建议**不要**做的

| 别做 | 为什么 |
|---|---|
| 自建完整云平台 | 司空 2 已经把"存/任务/实时"做完了，重复投入没意义；视频流量成本也难算。**尤其如果方向 3 走内部路线，云底座更该直接用现成的** |
| 从我们的界面派单 / 控飞（L3） | skill 明确说"大多数需求 L1+L2 就够"；控飞要人机闭环、权限、安全审查，周期和风险都不成比例 |
| 直接上方向 2 全量架构 | 权限 + 分布式存储 + Docker + 交付，是项目制投入；在客户没确定前会返工 |
| 复刻变化检测 | 司空 2 已经有（`ai_alert_record` + 变化区域接口），我们该做的是**把它的结果画到我们地图上** |
| 急着上向量库/语义检索 | 先用「地名→坐标 + 标签」，真实提问跑不顺再考虑 |
| **在拿到内部视角前，为"内部功能"做重投入** | 归属团队、是否重复建设、能否进主流程——**这三件事在外部判断不了**，先摸清再投入 |

## 七、一句话总结

**四个方向收敛成"一个索引 + 两个出口"；司空 2 从"方向 3 的赌注"变成"公共数据来源"，
而且它的接入路径今天已被实样验证；方向 2 的最大石头（离线瓦片）被司空 2 的官方方案搬走了一半。**

**方向 3 另加一个前提（用户补充）：它的成立条件是"大疆面试通过 → 变成内部功能更新"。**
按这个前提，它从"对外产品"变成"对内功能"——商业风险消失，但关键因素换成组织/归属/优先级，
**这三件事在外面判断不了，所以它不该排在路线前面，而该等内部视角。**

优先级：**司空 2 归档导入（3–5 天）→ 数据索引（2 周）→ 人的出口 / AI 的出口（并行，各 2 周）**，
可插拔瓦片源作为 1–2 天的小块插在中间。

**而无论方向 3 成不成，前面这三步都是净收益**：
- 方向 3 成了 → 它就是这个内部功能的**可运行原型**，直接拿去讲
- 方向 3 没成 → 它是方向 1 / 方向 4 的**公共底座**，照样是产品
