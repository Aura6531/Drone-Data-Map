# 双语（中文 / English）

> 用户 2026-10-15：「页面右上角增加一个切换语言的选项，中文英文可互相切换，
> 切换后所有按钮、显示文字、输出报告模板都要自动更换，这样我们之前的中文界面结果也可以拿来用了。」

---

## 一、先说一个和预期不同的实际情况

开始做之前我清点了一遍，结果和"之前是中文界面"这个印象不一样：

| 位置 | 实际情况 |
|---|---|
| **前端界面** | **本来就是英文**（2026-10-07 起按要求逐步改的）。JS 里**没有**中文用户文案 |
| **报告模板** | **本来就是英文**（`Marker Report — …`、`Generated:`、`Contents`、`Summary`、表头全英文） |
| **后端** | **191 条中文字符串** —— 其中相当一部分会直接显示在界面上（HTTP 错误、状态），这是真正的双语缺口 |

所以这次的工作重心是：**把后端文案和报告模板做成双语**，
再把前端的英文界面**接上中文译文**。

---

## 二、架构

### 两个文案表，分工明确

| 文件 | 内容 | 键的形式 |
|---|---|---|
| `Code/i18n.py` | 结构化文案：后端消息、报告模板 | 抽象键名（`report.title`），**支持参数** |
| `Code/i18n_ui.py` | 界面短文案：按钮、标题、提示 | **英文原串当键**（`"Load all tracks"`） |

### 为什么界面文案用**英文原串当键**

因为英文原文已经在代码里了，再加一层抽象键名只是多一处要对齐的东西。直接：

```js
t('Load all tracks')        // 英文环境 -> 原串；中文环境 -> "加载全部航迹"
```

**最大的好处：未翻译的串自动退回英文** —— 不会出现空白或裸露的键名。
于是覆盖面可以**渐进扩大**，不必一次改完（这个决定很关键，见第六节）。

代价：改了英文原文，译文就对不上了。`test_i18n.py` 会检查字典键的唯一性。

### 语言怎么定下来（优先级从高到低）

1. 查询串 `?lang=en|zh` —— 显式指定，测试与深链用
2. `Accept-Language` 请求头 —— 浏览器自带的
3. **服务端保存的设置**（`Project/_settings.json`）
4. 默认英文

**第 3 层是关键**：有些调用**没有请求上下文** —— 最典型的是 Windows 文件选择对话框
（它在独立线程里弹）。前端切换语言时会 `POST /api/lang` 通知后端一次，
之后这类调用就跟着用对语言。

语言存在 **thread-local** 里（`ThreadingHTTPServer` 每请求一个线程），
所以并发请求之间不会互相踩。`test_i18n.py` 有专门的断言钉住这一点。

### 接口

| 接口 | 用途 |
|---|---|
| `GET /api/i18n?lang=` | 前端启动/切换时拉整张表（`{lang, langs, messages}`） |
| `POST /api/lang {lang}` | 前端切换时通知后端（报告模板 + 文件对话框要用） |

**文案表住在后端，前端不留副本** —— 报告在后端生成，两处各存一份必然漂移。

## 三、前端：右上角的切换控件

```html
<div class="lang-switch" id="langSwitch">
  <label for="langSelect" data-i18n="ui.language">Language</label>
  <select id="langSelect">
    <option value="en">English</option>
    <option value="zh">中文</option>
  </select>
</div>
```

- **固定定位**在右上角（`position:fixed; top:8px; right:12px`）——
  三栏各自会滚动/折叠，放进哪一栏都会跟着动
- 毛玻璃观感与地图上那几个悬浮控件一致；刻意做小（它是"设置项"，不该抢注意力）
- 窄屏（≤900px）自动把"语言"两个字藏掉，只留下拉框
- 选择写进 `localStorage`（前端快）+ 后端（报告/对话框要用）

### 声明式替换

元素上加属性就自动换，**不需要为每个元素写 JS**：

| 属性 | 作用 |
|---|---|
| `data-i18n="英文原串"` | 换 `textContent` |
| `data-i18n-title="..."` | 换 `title` |
| `data-i18n-placeholder="..."` | 换 `placeholder` |

`applyI18n()` 是幂等的，可重复调用。`setLang()` 切换后会调 `onLangChanged()`
（如果页面定义了它），让已经渲染出来的动态内容也跟着换。

## 六、踩过的坑

| 坑 | 症状 | 根因 |
|---|---|---|
| **boot() 里读了 `document.documentElement.lang`** | **6 套前端测试连锁变红**（测试用的是简化 document mock，没有 `documentElement` → TypeError 打断整个 `boot()`） | 一条显示层的异常把地图、文件列表、项目下拉全废了。现在整段包 `try/catch`，并且读 `documentElement` 前判空 |
| **字典有重复键** | `/api/i18n` 的 JSON 有重复键，PowerShell 的 `ConvertFrom-Json` 直接报错 | 收了 `Loading…` 与 `loading…`、`Photos` 与 `photos`、`Markers` 出现两次… **JSON 里键比较大小写**，所以大小写不同也是同一个键。`test_i18n.py` 现在把它做成断言 |
| **`ast.Assign` 查不到带类型注解的赋值** | 重复键检查脚本误报"没找到 UI_ZH" | 带注解的是 `ast.AnnAssign`，不是 `Assign` |
| **测试锚在实现细节上** | 换了写法测试就假失败 | 例：`test_gallery_subtitle.js` 锚的是 `api('…')` 紧跟 `mode:readFrameMode()`；把 URL 挪进 `URLSearchParams` 后锚点落空。改成锚 URL 字符串本身 |

## 七、还没做的（**重要**）

**前端只有很小一部分接上了中文译文**：

```
data-i18n 属性: 2 处
t( 调用:        4 处
```

而清点出的**用户可见英文文案有 345 条**（按钮、提示、错误、图墙卡片、照片面板…）。
所以现在的状态是：

- ✅ **切换控件、持久化、接口、报告模板、后端消息翻译** —— 全部就绪并实测
- ✅ 中文译文表已经写了 **142 条**（覆盖界面骨架：按钮、面板标题、图墙、常见提示）
- ❌ **大部分前端文案还没接上**（调用点没包 `t()` / 没加 `data-i18n`）

因为"未翻译的串自动退回英文"，所以**现在切到中文是安全的**：
已覆盖的部分变中文，没覆盖的仍是英文，不会出现空白或键名。

### 继续做的方法（很机械）

1. 给 HTML 元素加 `data-i18n="<英文原文>"`（属性用 `data-i18n-title` / `placeholder`）
2. 给 JS 里用户可见的字符串包上 `t(...)`
3. 如果 `i18n_ui.UI_ZH` 里还没有这个串，补一条 `英文 -> 中文`

**注意**：`test_boot.js`／`test_frames_ui.js` 等静态测试会断言某些英文原文存在，
包 `t()` 时要留意（必要时同步更新断言）。

### 其他遗留

- **后端 191 条中文字符串只翻了一部分**（约 60 条进了 `i18n.py`）。
  剩下的包括 Windows 文件选择对话框、检测流程的诊断输出等。
  **诊断输出（`print` 到 stderr 的）用户看不到，优先级可以低**。
- `pano360_viewer.html` 的界面文案还没接。
- 语言切换后，已经渲染在页面上的**动态内容**（图墙卡片等）不会自动重画 ——
  需要 `onLangChanged()` 钩子，目前还没实现（骨架留了，函数没定义）。
