# 窄屏自适应（14 寸笔记本）—— 2026-10-13

> 起因（用户）：
> **「整体字号和按钮大小之前是在我家里的 4K 42 寸显示器上做的，当时觉得很不错，
> 现在在自己的 14 寸笔记本上看起来就有点过于拥挤了，而且即便我把网页缩放缩到了
> 80% 都不太够用。」**

## 一、先纠正一个容易误判的前提

**"屏幕尺寸"不是原因，"视口宽度的 CSS 像素数"才是。**

`innerWidth` 实测：**885**。

| | 42 寸 4K | 14 寸笔记本 |
|---|---|---|
| Windows 缩放 | 200% | 200%（推测） |
| 浏览器视口 | **≈1920 CSS px** | **885 CSS px** |

两块屏都是 200% 缩放，但**视口差了一倍多** —— 因为物理分辨率差一倍多。
这套布局是照 1920 定的，到 885 就彻底放不下。

> 还有一个容易混的点：**每个 CSS px 的物理大小也不同**
> （42 寸 ≈0.48 mm，14 寸 ≈0.18 mm，小近 3 倍）。
> 所以"字号显得挤"其实是两件事叠加：**视口窄了**（放不下）+ **物理尺度小了**（显小）。
> 浏览器缩放只能等比放大，会把栏宽一起放大，所以缩到 80% 反而更不够用。

## 二、885px 下原来的分配有多离谱

```
.layout:  380px(固定左栏) + 16 + 16 + 16 + 16 + 1fr + 1.12fr = 885
          └─ 左栏独占 380px = 43% 的屏幕
          └─ 中栏 ≈ 208px   ← 「Find flights at this position」被挤成竖排单字
          └─ 右栏 ≈ 233px   ← 视频和所有控件被切（Follow 按钮、Tianditu key）
```

**两个根因：**

1. **左栏是硬编码 `380px`，不随视口收缩** —— 视口越窄它占比越大
2. **只在大屏上验过，窄屏没有任何生效的断点** —— 原有的 `800px` / `1650px` 两个
   断点，一个太窄、一个几乎没用（后者只藏了个 `#photoLayerCount`）

另外 `applyVideoPanelLayout()` 里那个 `narrow-tools` 兜底（面板 < 780px 时
让标题栏按钮换行）**阈值卡在 780，而右栏实得 233px —— 兜底完全来不及生效**。

## 三、修法：左栏只由 `--left-w` 一个变量控制 + 四档断点

```css
.layout{grid-template-columns:var(--left-w,clamp(300px,22vw,380px)) minmax(0,1fr) minmax(0,1.12fr);
        gap:var(--gap,16px);padding:var(--pad,16px)}
```

四档（**必须按"由宽到窄"排列** —— CSS 同权重后写的覆盖先写的，顺序反了窄档会被宽档盖掉）：

| 断点 | 做什么 |
|---|---|
| `≤1900` | 左栏 clamp 到 300~380，间距/内边距随视口收 |
| `≤1400` | 左栏上限收到 320；`--ctrl-h` 36→32、`--ctrl-font` 13→12；**视频标题栏改 `flex-wrap:wrap`** |
| `≤1280` | 左栏变 **46px 窄条**，可一键折叠/展开（`.left-open` 改 `--left-w`） |
| `≤820` | 三栏改**上下堆叠**，`height:auto` 由整页滚动 |

### 两个关键决定

**① 折叠档放在 1280，不是更窄。**
用户视口是 885，先折左栏、**保住"地图与视频并排"**这个最要紧的对照关系；
一上来就堆叠的话，地图和视频就没法对着看了。885px 下实测：地图 377、视频 423，都够用。

**② 1400 档的标题栏换行用 CSS 兜底，不等 JS。**
`.narrow-tools` 是 JS 按**面板宽度**加的，而面板宽度是布局之后才知道的 ——
这一档必然太窄，等 JS 就来不及。所以直接在 CSS 里 `flex-wrap:wrap`。

## 四点五、字号改成**连续缩放**（用户 2026-10-13 追加要求）

用户问：「要不要把各个按钮的字号改成自动缩放的了」—— 做了，但**不是**简单用 `vw`。

### 为什么不用纯 vw

```css
/* 不要这样 */
--ctrl-font: 1.2vw;      /* ← 浏览器缩放会失效 */
```

**`vw` 不随浏览器缩放变化**：缩放改变的是"1px 有多大"，而不是"1vw 解析成多少 px"。
所以纯 vw 的字号对 `Ctrl +/-` 完全没反应 —— 用户按了发现没用。

正确写法是 `clamp(min, vw, max)`，**min/max 用 px**：

```css
body{--ctrl-font:clamp(12px, 0.72vw + 3px, 13px)}
```

- 窗口变窄 → 走中间那段 vw，字连续变小
- 用户缩放浏览器 → min/max 是 px，跟着变大变小（缩放仍然有效）
- **下限 12px 是硬底线** —— 再小就不好读了，宁可让行换行

实测（`test_layout_render.js` 量的真实计算值）：

```
1920px -> 13px      1400px -> 13px      1280px -> 12.216px
1100px -> 12px      885px  -> 12px
```

`1400px` 还是 13、`1280px` 已经是 12.216 —— 这正是"连续"而不是"跳变"。

### 一个坑：别在窄档里再写死字号

1400 档原来写了 `--ctrl-font:12px`，**它和 1900 档权重同级、写在后面，会把 clamp 整个盖掉**。
已删掉，并在测试里加了一条断言钉住：

```
[OK] 这一档不重复写 --ctrl-font（写了会盖掉 1900 档的 clamp）
[OK] min/max 是 px（纯 vw 会让 Ctrl+/- 缩放失效）
```

## 五、还修了一处"栏内横向滚动条"（915px）

用户 100% 缩放下视口 915px，中栏出现横向滚动条。用 CDP 逐元素量出真正的元凶：

```
多 93px  391->484  section.col.col-mid
元凶：div.card-tools      456px（栏只有 391）
      div.map-tools-right 456px（栏只有 391）
```

原因：`.card-tools button{flex:0 0 auto}` —— **按内容宽度、坚决不缩**。
单个看着合理，一行里几个加起来 456px，塞进 391px 的栏就撑破。

修法：给这一行显式允许收缩 + 文字省略：

```css
.card-tools.map-tools button,
.card-tools.map-tools select,
.card-tools.map-tools label,
.card-tools.map-tools .map-tools-right,
.card-tools.map-tools .photo-tools,
.card-tools.map-tools .photo-tools>*{flex:0 1 auto;min-width:0}
.card-tools.map-tools button{overflow:hidden;text-overflow:ellipsis;max-width:100%}
.card-tools.map-tools{min-width:0;max-width:100%}
```

修完 `col-mid` 从溢出列表里消失（**93px → 0**）。
剩下两条 `scrollW > clientW` 是 `overflow:hidden` 的元素（地图上的标签、按钮省略号），
**视觉上没有滚动条**，属于正常。

> 找溢出的方法值得复用：不要猜，用 CDP 把每个元素的 `scrollWidth - clientWidth`
> 和"内容比所在栏还宽"两类都打出来 ── 一次就定位到。


## 六、顺手修掉的一个后端 bug：`HEAD` 返回 501

控制台里那条红字：

```
Failed to load resource: the server responded with a status of 501
(Unsupported method ('HEAD'))   api/project/video?...MP4
```

后端只实现了 `do_GET` / `do_POST`。浏览器和某些播放器在决定要不要请求视频时
会先发一个 HEAD 探一下 —— 501 不影响播放（GET 能拿到），但控制台一片红，
而且**探测失败后有些客户端会改用更笨的方式（整段下载）**。

### 试错过程（值得留档）

**第一版**：把 `wfile` 换成一个"丢弃写入"的壳，走 do_GET。
→ 结果 **HEAD 响应 0 字节**，连接被关闭。
原因：HTTP/1.0 单请求模式下 `wfile` 与连接生命周期绑得很紧，替换它会连带
把 flush/close 语义弄坏。（这也说明"看着更优雅的一处生效"未必更好。）

**第二版（采用）**：**不动 `wfile`**，只置一个 `_head_only` 标志，
所有正文出口统一走 `self._write_body(data)`：

```python
def _write_body(self, data):
    if getattr(self, "_head_only", False):
        return 0
    self.wfile.write(data)
    return len(data)
```

共 8 处出口改过来（`json_response`、静态资源 ×2、视频/片段分块 ×2、照片、覆盖热力图…）。

实测：

```
HEAD /api/config   -> 200，响应头 Content-Length: 76 正确，正文 0 字节
GET  /api/config   -> 200，正文 76 字节
HEAD /project_geojson_preview.html -> 200，正文 0 字节
```

## 八、给你自己的判定清单

以后遇到"小屏上挤/被切"：

1. **先量 `innerWidth`**，不要看屏幕尺寸 —— 决定布局的是视口 CSS px
2. 看有没有**硬编码宽度**（`380px` 这种）—— 它不会随视口收
3. 看断点是否**真的生效**（顺序对不对、阈值是不是卡在刚好来不及的地方）
4. 用真浏览器量：`test_layout_render.js` 那套 CDP 探针可直接复用
5. 缩放不是解药 —— 它等比放大，栏宽一起放大
