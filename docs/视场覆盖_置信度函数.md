# 视场覆盖 · 综合置信度函数（设计 + 真实数据标定）

> 需求（用户 2026-10-12）：**能不能用一个「置信度」参数或函数，把"几何精度"和"观测到几次"
> 合成一个综合值？前期用经验系数试。**
>
> 结论：**能，而且已经设计出来并用真实遥测标定了系数。** 本文给出函数、系数、取值对照表。

---

## 〇、先纠正一个设计错误（第一版做完发现的）

第一版把三类误差**混在一个 σ 里**，结果主力俯角 −30° 的 `r_space` 掉到 **0.13（very_low）**。
实测发现这不合理 —— 因为两类误差的性质完全不同：

| 误差类别 | 例子 | 对覆盖图的影响 | 该不该进 footprint 置信度 |
|---|---|---|---|
| **A. 整体平移** | GNSS 定位、高程基准、地图配准 | 整幅图**一起平移**，格点间相对关系不变 | ❌ **不该** —— 它是"整幅图准不准"，不是"这一格准不准" |
| **B. 足迹形变** | 云台俯角误差、地表高差 | 改变足迹**边界位置** | ✅ 该 —— 决定"这一格到底在不在里面" |

**修正**：footprint 置信度**只吃 B**；A 单独作为 `geo_offset` 输出到 `accuracy_note`。

修正后 −30° 从 `0.13 / very_low` 变成 **`0.308` → 综合 `0.625 / medium`**，符合直觉。

## 一、函数设计（三层，各自可解释）

```
① r_space   空间可靠性   这个格子的边界位置有多确定   ← 姿态 + 地表高差
② r_support 观测支撑度   被观测了多少次、几次独立经过、看得多清
③ r_clip    边界可信度   结论是否依赖"人为收口"（type: clipped 要打折）

综合：conf = r_clip · ( r_space^w · r_support^(1-w) )^γ    并对 min 设下界
```

**为什么用几何平均而不是简单相乘**：两项都以 0~1 表达"这件事靠不靠谱"，
几何平均对"某一项特别低"敏感（不会被高的那项掩盖），这正是我们要的。
**但纯几何平均有个缺陷**：任一项为 0 就把结论彻底归零（哪怕另一项很好）。
所以加一个 `min_floor` 下界项兜底。

### 各层公式

```python
# ① 空间可靠性：Σ 是足迹边界的形变不确定度
σ_footprint = hypot( h·Δθ_pitch / sin²θ ,  Δh_terrain / tanθ )
r_space     = exp( -σ_footprint / σ_ref )          # σ_ref 默认 3.0 m
    ↑ 两项都随俯角变平而急剧增大 —— 这就是"远处怕姿态"的量化

# ② 观测支撑度：帧数 / 独立经过次数 / 解像度 三者的几何平均
r_support = ( min(1, frames/F_full) · min(1, passes/P_full) · min(1, GSD_good/GSD) ) ^ (1/3)

# ③ 边界可信度
r_clip = 0.5 if clipped else 1.0
```

**"独立经过次数（passes）"是关键**：同一格被 **300 帧连续覆盖**和
被 **3 次独立经过各覆盖 100 帧**，可信度差别很大。
实现上把覆盖该格的帧按时间聚类（间隔 > 1 s 算新的一次经过）。

## 二、系数表（**已定稿**，姿态精度经实测标定）

| 系数 | 定稿值 | 含义 | 依据 |
|---|---:|---|---|
| `d_pitch` | **0.15°** | 云台俯角不确定度 | 见下方「实测标定」——SRT 量化地板 0.1° + 一档余量 |
| `d_yaw` | **0.15°** | 云台偏航不确定度 | 同上（实测航向保持极稳，残差 0.029° = 量化地板） |
| `dh_terrain` | **0.5 m（常数，不做分区）** | 地表高差 | 见下方「为什么取 0.5 且不做分区」 |
| `d_gnss` | 1.5 m | GNSS 定位误差 | **不进 footprint 置信度**，单独输出 |
| `sigma_ref` | 3.0 m | σ 到这个值时 r_space = e⁻¹ | 锚定：σ = 3 个 1 m 格算"基本确定" |
| `grid` | **1 m** | 网格边长 | 用户定 |
| `frames_full` | 120 | 多少帧算"充分" | 主力俯角下 120 帧 ≈ 4 s 连续覆盖 |
| `passes_full` | 3 | 几次独立经过算"充分" | 多期观感经验值 |
| `gsd_good` | 0.10 m/px | 多细算"看得清" | 10 cm 足以判读地表设施 |
| `clip_penalty` | 0.5 | 收口边界打几折 | 收口是人为约定，非物理边界 |
| `w_space` / `γ` | 0.5 / 0.8 | 权重与整体压缩 | 让"两项都好"才到 high |

### 姿态精度实测标定（`d_pitch` 怎么定的）

查了原始 SRT 的读数精度，这是**硬事实**：

```
gb_yaw / gb_pitch / gb_roll   小数位 {1: 全部 36542 行}   最小间隔 0.1000°
latitude / longitude          6 位小数
rel_alt / abs_alt             3 位小数
focal_len / dzoom_ratio       2 位小数
```

- 姿态**量化到 0.1°**（量化半格 0.05°）→ 这是 `d_pitch` 的**硬地板**
- 司空 2 那份 36 秒里 `yaw` 只有 **13 个不同取值**，总变化 1.9°，
  局部线性拟合残差 **0.029°** —— 正好是量化地板，说明**除量化外几乎没有额外随机抖动**
- **但"读数分辨率"不等于"云台真实指向精度"** —— 后者是系统误差，
  **从 SRT 里测不出来**（需要专门做一次静态对靶试验）

**所以 `d_pitch` 取 0.15°**：量化地板 0.1° + 一档工程余量。
这是**乐观侧**的取值；要更保守可以取 0.3°，但需要有实测依据才合理。

> **悬停精度判断结论**：SRT 记录的悬停姿态"精度"实质上是 0.1° 的量化台阶，
> 云台真实的指向精度**当前无法从数据判断**。0.15° 是"不低估也不无端夸大"的取值。

### ⚠️ 一个反直觉但重要的结论

**在 `d_pitch = 0.15°` + `dh = 0.5 m` 下，−30° 附近「姿态项」和「高差项」几乎持平**
（1.02 m vs 0.87 m），更陡的俯角由姿态主导，更平的俯角**两项一起恶化**。

换句话说：

> **主力俯角段，云台精度和地表高差同等重要，谁也压不倒谁。**
> 所以**两件事都别放松**：既不能假设云台完美，也不能假设地面绝对平。

（上一版用 `dh=0.8` 时，高差项在 −25°~−50° 明显压过姿态项；
改成 0.5 后两者持平 —— 这也说明**这条系数只影响"谁主导"，不影响"结论有多可靠"的量级**。）

这直接影响取舍（俯角 −30°、高度 97 m）—— 见下一小节的定稿结论。

### 为什么取 0.5 且**不做分区**（用户 2026-10-12 定）

**先否决一个我自己的建议**：上一版我提"可按区域配，堤岸附近调高"——**这个建议是错的**。
理由很直接：

> **按区域配 `dh` ＝ 要先判断"哪里是堤岸"，那就是地形分类，又绕回地形数据了。**
> 既然决定了不做地形，`dh` 就必须是**一个常数**。

那常数取多少？三档实测对比（俯角 −30°、高度 97 m、`d_pitch=0.15°`）：

| `dh` | σ 合计 | r_space | 综合（反复观测+解像好） | 等级 |
|---:|---:|---:|---:|:--|
| 0.0 m（假装绝对平） | 1.02 m | 0.713 | 0.873 | **high** |
| **0.5 m（定稿）** | **1.33 m** | **0.641** | **0.837** | **high** |
| 0.8 m | 1.72 m | 0.564 | 0.795 | medium（压在临界线） |
| 2.0 m（堤岸量级） | 3.61 m | 0.300 | 0.478 | low |

**选 0.5 的两个理由**：

1. **不假装绝对平**：河滩确实有微起伏（几十厘米量级），取 0 是"假设我们知道它是平的"，
   而取 0.5 是"承认有微起伏" —— 这是诚实的一侧
2. **不压在临界线上**：0.8 会让主力俯角的综合分正好卡在 0.795（medium/low 之间），
   分类结果对系数过于敏感；0.5 给到 **0.837（high）**，稳。

**副作用（好的）**：`dh=0.5` 下，−25° 才开始掉到 low（0.552），
比 `dh=0` 的 −20° 更符合直觉 —— **越平越不可靠**这件事被表达出来了。

> 若将来真的引入地形数据（DEM/DSM），再把 `dh` 从"常数"升级为"逐格值"即可 ——
> **函数结构不用改**，只是 `dh` 从标量变成数组。这是留好的扩展点。

## 四、综合置信度取值对照（自检是否符合直觉）

| 情形 | 俯角 | 帧数 | 独立经过 | GSD | 收口 | r_space | r_support | **综合** | 等级 |
|---|---:|---:|---:|---:|:--:|---:|---:|---:|---|
| 正下视 + 久悬停 + 变焦详查 | −85° | 400 | 5 | 0.03 | 否 | 0.917 | 1.000 | **0.966** | high |
| 较陡俯角 + 中等观测 | −50° | 150 | 2 | 0.15 | 否 | 0.818 | 0.763 | **0.830** | high |
| **主力俯角 + 反复观测 + 解像好** | −30° | 300 | 3 | 0.08 | 否 | 0.641 | 1.000 | **0.837** | **high** |
| 主力俯角 + 反复观测 + 解像一般 | −30° | 300 | 3 | 0.20 | 否 | 0.641 | 0.794 | **0.763** | medium |
| 主力俯角 + 中等观测 | −30° | 150 | 2 | 0.15 | 否 | 0.641 | 0.687 | **0.751** | medium |
| 主力俯角 + 只扫过一秒 | −30° | 10 | 1 | 0.10 | 否 | 0.641 | 0.303 | **0.519** | low |
| 浅俯角 + 多次观测 + 解像差 | −15° | 200 | 4 | 0.40 | 否 | 0.245 | 0.630 | **0.478** | low |

**读法**：这张表和直觉一致 —— 正下视悬停最可信、浅俯角扫一眼最不可信、

−30°/300 帧要靠"3 次独立经过 + 解像 8 cm"才够到 high（0.837），
解像一般（20 cm）就掉到 medium（0.763）—— 说明**解像度是 `r_support` 里的关键一维**。

## 五、分级阈值与产物字段

| 综合值 | 等级 | 建议用法 |
|---:|---|---|
| ≥ 0.80 | **high** | 可直接作为判读依据 |
| 0.55 ~ 0.80 | medium | 可判读，但需注明几何不确定度 |
| 0.30 ~ 0.55 | low | 仅供参考 |
| < 0.30 | very_low | **不应作为判读依据**，只能说明"大致扫过" |

### 每条产出都带这些字段

```json
{
  "confidence": 0.625,
  "grade": "medium",
  "r_space": 0.308,
  "r_support": 1.0,
  "sigma_m": 3.53,
  "type": "hard_boundary",
  "accuracy_note": "平地模型；足迹形变不确定度 ±3.5 m；整幅图另含 ±1.5 m 定位偏移",
  "basis": { "frames": 300, "passes": 3, "gsd_m_per_px": 0.08, "clipped": false }
}
```

`type` 规则：
- `hard_boundary` —— 整条边都由真实几何算出（上边缘有一交点）
- `clipped` —— 该格/该边**部分或全部**依赖人为收口（`yImg=+1` 打过地平线）

> **实现建议**：栅格构建时同时记一个 `clipped_hit` 计数。
> 某格若只被 clipped 帧覆盖过 → `type: clipped`；若两种都有 → 按比例给 `r_clip`。

## 六、`d_pitch` 的实测依据与局限（已定稿为 0.15°）

**结论**：`d_pitch` / `d_yaw` 取 **0.15°**，依据如下（前面第二节已详述，这里只汇总判据）：

| 判据 | 实测值 | 含义 |
|---|---|---|
| SRT 姿态读数精度 | `gb_yaw/gb_pitch/gb_roll` 全部 **1 位小数**，最小间隔 **0.1000°** | 量化步长 0.1°，**硬地板** |
| 航向保持稳定性 | 司空 2 那份 36 s 内 yaw 只变 1.9°，局部拟合残差 **0.029°** | 除量化外几乎无额外抖动 |
| 选值 | **0.15°** = 0.1° + 一档工程余量 | 不低估、也不无端夸大 |

### 一个尚未消除的局限（要么接受，要么做专门试验）

**"读数分辨率" ≠ "云台真实指向精度"**。0.1° 能测出来的是"读数台阶"，
而云台相对地面的**系统指向误差**（安装偏差、增稳算法残差）**从 SRT 里判断不了**。

**若要把 `d_pitch` 压到 0.1°（而不是 0.15°）或更可信，需要一次专门试验**：

- 做法：无人机**悬停不动**、云台**锁死**，对着一个远处已知目标录 1 分钟
- 看 SRT 里 `gb_pitch` 的**波动范围**：稳定在 0.1° 内 → 量化主导；抖动 ±0.3° → 增稳残差主导
- 副作用：同时能看到 `gb_yaw` 的漂移（决定 `d_yaw`）
- 更强的做法：对地面已知靶标（如十字标）拍一张，用反投影算实际指向，与 SRT 读数比对 ——
  这能直接量化**系统指向误差**，是唯一能把它测出来的方法

**在此之前**，`accuracy_note` 里应写明：**"姿态精度按量化地板 + 余量估计，未经对靶实测"**。

## 七、这个函数怎么用（两种用法）

### 用法 1：查询单个位置

```http
GET /api/project/coverage/query?lat=23.0471&lng=114.1042
```
```json
{
  "covered": true,
  "confidence": 0.625, "grade": "medium",
  "best": { "frames": 300, "passes": 3, "gsd_m_per_px": 0.08,
            "can_resolve_cm": 8, "zoom_used": true,
            "time_range": ["00:03:12", "00:03:29"] },
  "why": "主力俯角 −30°，足迹形变不确定度 ±3.5 m；被 3 次独立经过反复观测，解像 8 cm/px",
  "caveat": "平地假设；河岸高差 >1 m 处边界会偏移"
}
```

### 用法 2：热力图分档

用置信度而不是帧数来上色，并且**分级而非连续渐变**（4 档），
让"可信 / 需注意 / 不可信"一眼可辨 —— 避免连续色带被误读为精确值。

## 八、一句话总结（**系数已定稿，可直接实施**）

**能合成一个综合置信度**，而且它的行为是对的：

- 决定它的**不是**"看了几次"一个数，而是"**边界有多确定 × 看得够不够多 × 看得够不够清**"
- 主力俯角（−30°）下，"看 300 帧 + 3 次独立经过 + 解像 8 cm" 才够到 **high（0.837）**；
  解像退到 20 cm 就掉成 medium —— **解像度是 `r_support` 里的关键一维**
- 依赖人为收口的地方自动降级（同条件下从 0.763 掉到 0.379）

### 定稿系数（可直接写进代码）

```python
GRID            = 1.0     # m，用户定
D_PITCH         = 0.15    # ° 量化地板 0.1° + 一档余量（已实测标定）
D_YAW           = 0.15    # ° 同上
DH_TERRAIN      = 0.5     # m 常数，不做分区（用户定：不做堤岸判断）
D_GNSS          = 1.5     # m，只进 accuracy_note，不进 footprint 置信度
SIGMA_REF       = 3.0     # m σ 到这个值时 r_space = e^-1
FRAMES_FULL     = 120     # 帧
PASSES_FULL     = 3       # 次独立经过
GSD_GOOD        = 0.10    # m/px
CLIP_PENALTY    = 0.5
W_SPACE, GAMMA  = 0.5, 0.8
```

### 主力俯角（−30°、高度 97 m）下的最终结论

```
σ_footprint = 1.33 m   →   r_space = 0.641 (medium)
综合置信度（300 帧 / 3 次经过 / 8 cm 解像） = 0.837 → high
```

### 一个留好的扩展点

如果将来真的引入地形数据（DEM/DSM），把 `DH_TERRAIN` 从**标量改成逐格数组**即可 ——
**函数结构一个字都不用改**。这是当初就没写死分区逻辑的原因。
