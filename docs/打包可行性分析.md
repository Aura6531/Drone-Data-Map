# 打包成可分发 exe —— 可行性分析

> 结论先行：**可行，而且不难**。推荐 **PyInstaller 目录版（绿色版）+ 可选 Inno Setup 安装包**，
> 界面沿用系统自带的 Edge/Chrome（`--app` 模式，看起来就是个桌面程序），
> 把 Python 运行时、Pillow / python-docx、Tcl/Tk、ffmpeg、Leaflet 一起打进去。
> 成品预计 **130~160MB**（自解压/7z 后 60~80MB），重量几乎全在 ffmpeg。
> **必须改的代码只有 3 处**（见 §5），其中第 1 处不改会**丢用户项目**。
>
> 本文档只是分析，没有改任何代码。文中的体积/依赖都是在本机实测出来的。

---

## 1. 目标环境（干净 Win10/Win11）意味着什么

| 对方机器的情况 | 对我们的影响 | 结论 |
|---|---|---|
| 没有 Python（不会预装） | 后端跑不起来 | 必须自带 Python 运行时 |
| 没有 ffmpeg | 抽帧、播放代理全废 | 必须自带（且要改查找顺序） |
| **自带 Edge**（Win10/11 都有，Chromium 内核） | 界面天然可用 | **不用打包浏览器** —— 省掉 Electron/CEF 的 150MB+ |
| 可能没有外网 / 有内网 | 底图瓦片、逆地理编码要外网 | 至少 Leaflet 不能走 CDN（见 §5 第 3 点） |
| 没有天地图 key | 地名搜索、底图不可用 | 要么带 key，要么首次运行让使用者填（见 §6.2） |

| 组件 | 实测 | 是否必须 | 用途 / 说明 |
|---|---|---|---|

## 3. 打包路线对比

| 路线 | 原理 | 体积 | 启动 | 稳定性 / 坑 | 工作量 |
|---|---|---|---|---|---|
| **A. PyInstaller 目录版**（推荐） | 官方 Python 运行时 + 依赖 + 我们的代码，输出一个文件夹，里面有 exe | 基础 ~45–70MB（不含 ffmpeg） | 快 | 坑最少；可加图标、版本信息 | 小（半天级） |
| B. PyInstaller 单文件 | 一个 exe，启动时解压到临时目录 | 同上 | **慢**（首次几秒~十几秒） | **路径会指向临时目录**（不改代码=丢数据）+ 杀软误报率高 | 小但不建议 |
| C. Embeddable Python + 启动器 | 官方 embeddable zip（最小 ~11MB） | 最小 | 快 | **不含 tkinter** → 选文件对话框要自己拼 Tcl/Tk，反而更麻烦 | 中 |
| D. Nuitka 编译 | 编译成真正的 exe | 与 A 相当 | 最快 | 构建要 MSVC、耗时十几分钟；Python 3.14 支持需验证 | 中 |
| E. 重写成 Go / C# | 原生 exe，最小 ~20MB | 最小 | 最快 | Word 生成（docx 库）、图像合成、SRT 解析全要重做 | **很大** → 本次不做 |

**选 A**：改动最小、风险最低，而且"目录版 + 一个启动 exe"对使用者来说就是"解压、双击"，符合绿色版心智。
想要安装体验（开始菜单、卸载）就在 A 外面套一层 **Inno Setup**（免费、成熟）。

## 4. ffmpeg 怎么带（体积大头 + 授权）

**需求**：既要**解码 4K HEVC**，又要 **H.264 编码**。
后者不是可选项 —— 代码注释里写得很清楚：4K HEVC 原片，Chrome 在 Windows 上不支持软件解 HEVC、
Firefox 完全不支持，所以有"按需转码成 H.264 片段"的网页播放代理；
前端还有"原片 7 秒没就绪就自动切转码片段"的兜底。**去掉 x264 就等于去掉 4K 视频播放能力。**

| 选项 | 体积（官方数据/实测） | 说明 |
|---|---|---|
| gyan.dev **full 静态**（本机这个） | 3 个 exe 共 **637 MB** ✗ | 太大，不可用 |
| gyan.dev **release essentials 静态** | 包 7z **34 MB**；解包后**只取 ffmpeg.exe + ffprobe.exe** ≈ **70–90 MB** | ✅ **推荐**：含 libx264/libx265，够用 |
| BtbN **LGPL shared** | 更小 | 授权更宽松，但**要先确认它带不带 H.264 编码**（`ffmpeg -encoders \| findstr 264`）；不带就得放弃代理功能 |

**授权**：gyan.dev 的包是 **GPLv3 静态构建**（含 x264/x265）。分发给别人时要在包里放它的
LICENSE / README 并注明来源与版本 —— 合规成本很低，但不能省。
（参考：[gyan.dev FFmpeg Builds](https://www.gyan.dev/ffmpeg/builds/)，其页面明确写着
"All builds are 64-bit, static and licensed as GPLv3"、要求 Windows 10 以上。）

**落地**：ffmpeg 放 `程序目录\ffmpeg\`，并让 `find_ffmpeg()` **优先**找这里（现在只找 PATH 和
`C:\Program Files\ffmpeg\...`）。

## 5. 必须改的代码（就 3 处，都很小）

1. **路径基准（最关键的一条）**
   现在：`CODE_DIR = Path(__file__).resolve().parent`、`TEST_DIR = CODE_DIR.parent`，
   `Data/`、`Project/`、`report_cache/`、`video_proxy/`、`tile_cache/` 都挂在 `TEST_DIR` 下。
   冻结打包后 `__file__` 会指向**包内部**（单文件模式下更是**每次启动都变的临时目录**）
   → **用户导入的数据、标记点会写进临时目录，一关程序就没了**。
   改法：`if getattr(sys, "frozen", False): TEST_DIR = Path(sys.executable).parent`。
   这一条不改，单文件模式必炸；目录模式虽然"碰巧"能对，也应该显式写死。

2. **ffmpeg 查找顺序**：先找 `程序目录\ffmpeg\ffmpeg.exe`（及 ffprobe），再退回 PATH 与常见安装路径。

3. **两个"随包文件"的位置**
   - 天地图 key：现在在 `Code/tianditu_key.txt`（包内部）→ 挪到程序目录（或在包内但可写）
   - `vendor/leaflet.js`、`vendor/leaflet.css`：**仓库里现在没有这个目录**，页面靠 CDN
     → 打包前必须补进去（服务端 `/vendor/` 路由已经写好了，放文件即可）

**强烈建议一起做的体验项**（不是必需，但不做会显得不像"一个程序"）：
启动后自动用 Edge 以 `--app=http://127.0.0.1:<端口>` 打开（无地址栏，像桌面程序）；
托盘图标或"退出"按钮（现在只能关那个黑窗口）；端口被占用时自动换端口。

## 6. 分发给别人要处理的 8 个坑

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | **杀软误报** | Defender/360 拦下 PyInstaller 的 exe | 用目录版（不套壳不加压缩）；说明里写"加入信任"；买代码签名证书约 2000~4000 元/年（个人分发通常不值） |
| 2 | **天地图 key 共用配额** | 多人用同一个 key → 超额后底图/搜索失败 | 包里带 key + 说明"人多要自己申请"；或首次运行引导填写（现在改 key 文件不用重启，已支持） |
| 3 | 装到 Program Files 写不进去 | 导入数据失败 | 绿色版放任意用户目录；安装包默认装 `%LOCALAPPDATA%` |
| 4 | 端口冲突 | 8000 被占（现在会提示"已有服务在应答"） | 自动挑空闲端口并在标题/页面显示实际端口 |
| 5 | 关不掉 | 现在只能关黑窗口 | 托盘图标 / 页面上的"退出"按钮 |
| 6 | 内网/断网 | Leaflet 走 CDN → 页面直接白屏 | 补 `vendor/`；完全离线的地图底图不在本次范围 |
| 7 | **项目存的是本机绝对路径** | 换电脑后项目打不开（如 `A:\Test\Data\...`） | 说明里写清"换机器要重新导入数据"；以后可考虑相对路径/重定位功能 |
| 8 | 老 CPU / 系统版本 | 少见的启动崩溃 | 目标 Win10/11 64 位；essentials 构建已避开 libvvenc 那类老 CPU 问题 |

## 7. 成品体积预估

| 项 | 大小 |
|---|---|
| Python 运行时 + 必需标准库（PyInstaller 自动裁剪） | ~25–35 MB |
| Pillow + python-docx + lxml | ~27 MB |
| Tcl/Tk | ~5 MB |
| 我们自己的代码 + 前端 + Leaflet | ~1 MB |
| ffmpeg.exe + ffprobe.exe（essentials） | ~70–90 MB |
| **合计** | **≈ 130–160 MB**（7z/自解压后 ~60–80 MB） |

对照：如果走 Electron/CEF 打包浏览器，光内核就 +150MB —— 所以"**沿用对方的 Edge**"是省体积的关键决策。

## 8. 验证方案（怎么证明在别人机器上真能跑）

用 **Windows 沙盒**（Win10/11 专业版自带，一键开一个全新环境）把包拷进去跑全流程：
**导入数据 → 点地图定位 → 播放 4K 视频 → 右键取点命名 → 生成 Word 报告**。
家庭版没沙盒就用 Hyper-V 或找一台同事的电脑。

四个重点：
1. 建个标记点、关掉程序、重开 → **还在**（验 §5 第 1 点，这是最容易翻车的地方）
2. 4K HEVC 能播（说明 x264/代理生效）
3. Word 报告能生成（说明 Pillow + python-docx + lxml 齐）
4. 底图能出（说明 key + 外网 + vendor 都 OK）

## 10. 需要你定的 4 件事

1. **交付形式**：绿色版（解压即用，最省事）/ 安装包 / 两个都要
2. **数据放哪**：程序目录内（便携：拷走程序=带走数据）/ `%LOCALAPPDATA%`（安装包常规做法）
3. **关闭方式**：托盘图标（推荐）/ 网页里加"退出"按钮 / 关掉黑窗口即退出
4. **天地图 key**：沿用你的 key 一起发（简单，但共用配额）/ 留空让使用者自己申请（更规范）

## 11. 明确不做（避免跑偏）

- ❌ 不引入 Electron / CEF / WebView2 去打包浏览器（+150MB，只为"看起来像原生"）
- ❌ 不重写后端（Go/C# 版是另一个量级的工程，收益只有体积）
- ❌ 不监听 `0.0.0.0`（会弹防火墙，还等于把服务暴露到局域网；现在就是 `127.0.0.1`，保持）
- ❌ 不做离线地图底图（本次范围外）
