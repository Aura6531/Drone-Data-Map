## 一、接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/project/coverage/list?name=` | 该项目下每个 SRT 的覆盖状态（建过没有 / 是否过期 / 摘要） |
| POST | `/api/project/coverage/build` | `{project_name, srt, cell, force}` → 建栅格（已有且不旧则复用） |
| GET | `/api/project/coverage/query?name=&npz=&lat=&lng=` | **点查询**：这点被拍到没有、看多清、多大把握 |
| GET | `/api/project/coverage/heatmap?name=&npz=&metric=&gsd_max=&overlay=&threshold=` | 热力图 PNG（`metric=count\|gsd`；`overlay=1` 叠加矢量轮廓） |
| POST | `/api/project/coverage/export` | `{project_name, npz, metric, threshold, gsd_max, inline}` → 矢量 GeoJSON（落盘 + 可选内联返回） |
| GET | `/api/project/coverage/file?name=&file=` | 取回导出的 `.geojson / .json / .png` |

### 落盘规则（改了一条设计）

覆盖网格存在**项目目录下**，不再散在原始素材目录里：

```
Project/<项目名>/coverage/<视频名>.<源路径哈希8位>.npz     覆盖栅格
Project/<项目名>/coverage/<同名>.json                     摘要
Project/<项目名>/coverage/<同名>.meta.json               源 SRT 路径 + mtime
Project/<项目名>/coverage/<同名>_count1.geojson           导出的矢量
```

带哈希是为了**不同架次的同名视频不会互撞**；`meta.json` 里记 SRT 的 mtime，
所以**源数据换了、界面会提示"needs rebuild"**，不会拿旧网格糊弄。

### 安全校验（都实测过）

| 攻击面 | 防护 | 实测 |
|---|---|---|
| 用 `srt` 参数读任意文件（如 `notepad.exe`） | 必须是 `.srt`，且**必须落在该项目登记的文件夹里** | 400 拒绝 |
| 用 `npz` 参数读任意文件 | 只认**项目 coverage/ 目录下的 `.npz`** | 400 拒绝（含 `..\..\project.json`、`A:\Windows\win.ini`） |
| 用 `file` 参数穿越目录 | 取 `Path(fn).name` 剥掉路径 + 限扩展名 + 限目录 | 400 拒绝（含 `..%5C..%5C`） |

## 二、界面

地图工具行右侧新增 **`Coverage`** 按钮，点开是两行面板（默认收起，不占地图高度）：

```
Flight  [DJI_..._V (ready) ▾]  [Build]   状态文字…
Show    [Observed (times seen) ▾]  at least [1] frames
        Opacity [====] [Show] [Export]     提示 / 导出链接
```

**三种展示**：

| 选项 | 画什么 | 用什么 |
|---|---|---|
| `Observed (times seen)` | 观测次数热力图（越红=被拍到的帧数越多） | `imageOverlay` 贴 PNG |
| `Sharpness (best detail)` | 解像度热力图（越红=米/像素越小） | 同上，`metric=gsd` |
| `Coverage area (polygon)` | 覆盖范围矢量多边形 | `L.geoJSON` + 弹窗显示面积/格数/洞数 |

**另外两处**：

- **点查询**：面板开着时，在地图上点任意位置 → 地图下方出现结果块：
  置信度 + 分级徽章、观测帧数/独立经过次数、最优解像（可判读多少厘米）、
  最清晰那一刻的时间/俯角/高度、边界不确定度、以及 `accuracy_note` 的说明。
- **覆盖图例**：浮在地图**右下角**（航迹图例在左下角，两块独立元素不重叠），
  画出色带 + 两端含义 + 架次名。

## 三、这次改对的两个关键点

### ① 热力图的定位数学（最容易悄悄错的地方）

`imageOverlay` 需要经纬度范围，前端从摘要的 `origin / grid / half_m` 反推。
算错的话**图还是画出来了，只是贴错位置** —— 这种错不看图看不出来。

`test_coverage_ui.js` 用**真实网格摘要**（司空 2 样本 2641×2641 @1 m）对照独立算出的边界：

```
南界 22.9517111  北界 22.9756029  西界 113.7577358  东界 113.7835022   ✓ 完全一致
南北跨度 = 2641.0 m = 2641 行 × 1 m                                  ✓
```

同时钉住"南北不能搞反"（搞反了图会上下颠倒）和"缺字段返回 null 而不是编一个范围"。

### ② 色带前后端必须一致

前端图例的颜色写死在页面里，后端渲染色带写死在 Python 里 —— 两边一旦不一致，
会出现**「图例说这颜色代表很多、图上却是别的意思」**，而且看起来还挺正常。

`test_coverage_ui.js` 里加了断言：跑一次带 numpy 的 Python 取出 `coverage_api._BANDS`，
逐档比对前端 `COVERAGE_BANDS`（后端第 0 档 `#f2f2f2` 是"无覆盖"底色，前端单独表示）。

```
后端 6 档 / 前端 5 档                                        ✓
前端"无覆盖"色 = 后端 _BANDS[0]  #f2f2f2                      ✓
五档渐深色逐一对应  #c6e2ff #96e8af #ffe082 #ffa05a #de3c3c   ✓
```

> 顺手**消掉了一处重复实现**：热力图渲染原来在 `coverage_build.py`（命令行）
> 和 `coverage_api.py`（接口）各有一份。现在只有一份（`coverage_api`），
> 命令行反过来调它 —— 配色只有一个地方要改。

## 四、实测结果

### 接口（对运行中的服务，`_test_coverage_http.py` + `_test_coverage_file.py`）

```
清单 / 缺参数报错 / 构建（复用）/ 越权拒绝 / 点查询 9 个字段 /
路径穿越拒绝（3 种）/ 热力图 2 指标 + 叠加 / 矢量导出 2 组
取文件：正常取回 + 7 种非法路径全拒 + 不存在文件 + 缺参数
                                            全部通过
```

点查询实例（司空 2 样本中心点）：

```
置信度 0.9237 (high)   帧 86   解像 0.0347 m/px   type=hard_boundary
accuracy_note: Flat-ground model; footprint boundary is uncertain to about ±1.3 m.
               The whole map also carries a ±1.5 m positioning offset.
               Attitude accuracy is estimated from the SRT quantisation step plus a
               safety margin, and has not been verified against a surveyed target.
```

> **界面文案一律英文**（2026-10-13 补）：`accuracy_note`、`reason`（未覆盖的两句）、
> 图墙里"跳过了哪些架次"的原因，全部改成英文。
> 页面里 `show(...)` / `textContent=` / `innerHTML=` 里的字符串**扫描确认无中文**；
> 剩下的中文只在**代码注释**和**命令行工具的输出**里（那是给开发者看的，按约定不动）。
>
> 注意：`accuracy_note` 是**查询时现算的**，不落盘，
> 所以改文案**不需要重建网格**，重启服务即可。

### 测试套件

```
18 套：16 通过，2 失败（check_page.js、test_report.py —— 均为既有问题）
有 numpy 与无 numpy 两种环境结果一致（无 numpy 时覆盖相关的 2 套明确 [SKIP]）
```

### 热力图外观

`api_heat_count.png`：分档色带清晰，能一眼看出两处驻留最久的区域（红色块）、
中间过渡（橙→黄→绿→蓝）、以及边缘的扫掠带。配色刻意用**分档**而非连续渐变 ——
连续色带会被误读成"精确值"。
