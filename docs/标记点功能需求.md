## 〇、一句话需求

在视频画面上右键标记一个位置，得到**一个可管理的标记点**：
能在地图上看到、能在列表里管理、能一键回到那一帧、能导出成表格和 Word 报告，
并且**关掉页面下次打开仍然在**。

### 2.1 位置与布局

放在**右栏下半部**（视频面板下方的空白区）。

```
右栏（#colRight）=
    视频面板      ← 改为「按内容定高」：.video-panel .video-dialog 由 flex:1 改 flex:0 0 auto
  + 标记点列表    ← flex:1，占余下空间，内部滚动
```

### 2.2 列表内容与交互（逐条）

1. **表头**：一个**总体全选复选框**（子项部分选中时呈半选态），外加四个批量按钮：
   - 批量删除（**要二次确认**）
   - 批量导出 KML
   - 批量复制经纬度和名称
   - 一键生成 Word 报告
2. **每一行**：`[复选框] 名称  纬度  经度  [×]`
   - 行首复选框：参与批量操作
   - 行尾 `×`：**单独删除**该点（要二次确认）
3. **点行本身（非复选框区）→ 自动跳转**：
   - **左侧轨迹地图**：`map.setView(该点经纬度, 16)` —— **固定 16 级**
   - **右侧视频**：切到该点记录的 `video`，并把播放位置跳到 `time`
   - 只**定位**到那一帧，**不自动播放**（默认暂停，点播放按钮才继续）
4. **排序**：按**创建时间**（**新的在上面**）
5. 列表为空时显示一句占位提示（如「还没有标记点：在视频画面上右键即可标记」）
6. **命名框**：打开时预填「项目名-序号」默认名（并整段选中，打字即替换）；
   名字**不能与已有标记点重复** —— 忽略大小写与多余空格后同名就不入库，
   停在弹窗里给出提示让用户改

### 2.3 批量操作细则

| 按钮 | 要求 |
|---|---|
| **批量删除** | 删掉所有勾选的点（含地图上的标记），保存并刷新列表；二次确认 |
| **批量复制经纬度和名称** | 写入剪贴板，**制表符分隔 + 一行表头**；**列只有三列：名称、纬度、经度**。粘到 Excel 应自动分成三列 |
| **批量导出 KML** | 前端生成 KML（每个点一个 `<Placemark>`，名称用标记名；`<description>` 里带**视频文件 + 视频时间**），浏览器下载；文件名形如 `标记点_<项目名>_<日期>.kml` |
| **一键生成 Word 报告** | 见第三节 |

> 批量操作**只作用于勾选的点**。**一个都没勾时点这些按钮 → 只在页面上提示「请先选择要导出的标记点」**，不发请求、不生成空文件。

## 三、一键生成 Word 报告（批次② ✅ 已完成）

### 3.1 范围与提示

- **只包含勾选的点**。
- **一个都没勾 → 页面端提示**，不生成。

### 3.2 报告结构

```
标题：标记点报告 —— 项目「<项目名>」        （生成时间、点数）
──────────────────────────────────────
目录          ← 每个点一条，点击可跳转到对应章节   ★ 关键要求 ★
──────────────────────────────────────
汇总表（一行一个点）
  序号 | 名称 | 纬度 | 经度 | 所在位置 | 视频文件 | 视频时间
──────────────────────────────────────
一、<名称 1>              ← 章节标题（带书签）
    名称 / 经纬度 / 所在位置 / 视频文件 / 视频时间
    图 1  目标点视频截图
    图 2  目标点地图截图
二、<名称 2>
    …
```

**目录必须能在 Word 内点击跳转** —— 实现方式：**书签 + 超链接**（直接写进 docx 的 XML），
**不要用需要按 F9 刷新的域代码目录**（`w:fldSimple TOC`）—— 用户要求"打开就能点"。

### 3.3 每一节的内容来源

| 内容 | 来源 |
|---|---|
| 名称 / 经纬度 / 视频文件 / 视频时间 | 标记点自身字段 |
| **所在位置**（到「XX镇XX村」级别）| **天地图逆地理编码**（服务端调用，key 在服务端）。取不到就**留空并标「未解析」**，**绝不编造** |
| **目标点视频截图** | 服务端 **ffmpeg 抽帧**：`-ss <time> -i <原片> -frames:v 1 out.png`（抽**原片**不是代理，所以是原始分辨率）|
| **目标点地图截图** | 服务端**拼瓦片**（瓦片本来就走本地代理 + 磁盘缓存），用 **Pillow** 拼接并在图上标出目标点。**底图必须用客户当前选择的那一种**（选街道就街道、选卫星就卫星）—— 前端把当前底图类型传给后端 |

> 地图截图**不要**用前端 canvas 截图：瓦片跨域会污染画布，拿不到图。

### 3.4 截图尺寸（生成时给用户选择）

- **原分辨率** —— 4K 一帧原样嵌入（报告体积大）
- **压缩至 320 ppi** —— 按 A4 正文宽度（约 19.7 cm）折算到 320 ppi，即**约 2480 px 宽**（打印清晰、体积友好）

## 六、已知坑（踩过，写在这里省时间）

1. **别把后端起成两个** —— 服务端开了 `allow_reuse_address`，两个进程能同时绑 8000，
   请求被随机分配给其中一个，会出现「改了代码却 404 / 服务时通时不通」的假象。
   起之前先 `netstat -ano | findstr :8000`，有占用先杀掉。
2. **写文件前必须先 `read`** —— 本仓库的写入工具要求先读过该文件；
   用 pwsh 读**不算**，直接用 read 工具读 2 行即可解锁。
3. **写断言别用裸词** —— 注释里也会出现同样的字样（本项目踩过多次）；
   也不要用 `\}` 卡规则行尾（规则后面常还有别的声明）。
4. **后端必须以完全权限启动**，否则 `Code/`、`Project/`、`Data/` 写入报 `[WinError 5]`。
5. 地图截图的底图类型要**由前端传参**，不能写死街道图 —— 用户明确要求跟随当前选择。
6. **ffmpeg 直接写的 JPEG，python-docx 不认**：它写 `SOI + COM("Lavc…")`，
   docx 只认 JFIF/Exif，会抛 `UnrecognizedImageError`，**而且消息是空的**
   （接口只回 `{"error": ""}`）。抽帧必须先出 PNG 再用 Pillow 转 JPEG。
   `test_report.py` 已把这条钉住（断言 `SOI+APP0` 且 docx 能读）。
